# 聊天功能規格（Chat Specification）

建立：2026-10-01。狀態：**已實作（階段 A–C 主要功能）**，最後對齊實作：2026-10-05。與規劃不同或尚未完成之處以「目前實作」標示。

## 1. 文件目的

本文件定義後台「聊天」功能：參考 LINE Official Account Manager 的聊天、聯絡人、篩選傳訊與聊天設定，讓後台管理員在本平台直接查看與回覆 LINE 對話，並把聯絡對象、標籤、對話記事本與案件整合在一起。

適用原則：

- **Small Team First**：服務 1–3 位後台管理員，不做客服中心等級的派工、排班與績效（見[聯絡人管理規格](聯絡人管理規格.md)）。
- **單台 PC**：伺服器為一台 PC，資料庫為 SQLite；所有上限、輪詢頻率與保存期限都以此為前提，集中定義於後端一處，日後可統一調高。
- **沿用既有**：沿用現有 Webhook、`line_messages`、`recipients`、發送工作（`send_jobs`／`send_deliveries`）、單次預約與訊息編輯器，不另建一套。

相關文件：[聯絡人管理規格](聯絡人管理規格.md)（聯絡對象、標籤、備註、對話記事本、自訂篩選條件）、[案件管理流程規格](案件管理流程規格.md)、[LINE 訊息格式與編輯器設計](LINE訊息格式與編輯器設計.md)、[LINE API 原始參數對照](聯絡人管理規格.md#71-line-api-原始參數對照source-of-truth)。

## 3. LINE 平台限制（設計前提）

| 限制 | 影響 | 確認狀態 |
|---|---|---|
| Webhook 只傳送使用者端的事件；在 LINE Official Account Manager 由人工送出的訊息不會傳到本平台 | 若同事仍在 LINE 官方後台回覆，本平台的對話會缺少那些訊息。UI 須提示「僅顯示經本平台收發的訊息」，並建議統一在本平台回覆 | 已知行為 |
| Reply 不計入訊息額度；`replyToken` 須在收到 Webhook 後 1 分鐘內使用、只能用一次、一次最多 5 個訊息框；官方註明時限可能不另行通知調整 | 對方每傳一則訊息，只有一次 1 分鐘內的免費回覆機會；同一則訊息補送第二次、超過 1 分鐘或主動傳訊，都只能用 push | 已確認（官方 API 說明） |
| Push、Multicast、Broadcast、Narrowcast 計入每月訊息額度，依收到的人數計算（傳到 5 人群組算 5 則）；傳給已封鎖者或不存在的使用者不計 | 送出前若將使用 push，UI 須標示會使用的則數；篩選傳訊一律計入額度 | 已確認（官方計費說明） |
| 在 LINE Official Account Manager 由人工一對一回覆不計入額度 | 第三方系統（含 SHOPLINE 等訊息整合）經 Messaging API 送出的訊息仍依上列規則計費，無法以一般帳號完全取代官方聊天而不耗用額度；本平台採「方案 C」，見 7.1 | 已知行為 |
| 圖片、影片、音訊、檔案需透過 `GET /v2/bot/message/{messageId}/content` 另行下載，LINE 只保留一段時間 | 階段 C 需在收到時就下載保存，否則日後無法補抓 | 已知行為 |
| 群組發話者的名稱需以 `GET /v2/bot/group/{groupId}/member/{userId}` 查詢 | 需快取群組成員名稱，避免每次顯示都呼叫 API | 已知行為 |
| 使用者在 LINE 端是否「已讀」本平台送出的訊息，Webhook 不提供 | 不顯示對方已讀狀態 | 已知行為 |
| LINE 官方後台的聊天標籤、記事本、預設訊息、回應時間無對應 API | 本平台的資料與 LINE 官方後台各自獨立、不同步 | 已知行為 |
| 將使用者訊息標為已讀（`markAsReadToken`）、Loading 動畫、引用回覆（`quoteToken`） | 屬加分功能，實作前確認方案與帳號是否可用 | **待驗證** |

## 4. 導覽與畫面結構

不照抄 LINE 的選單。依本平台現有導覽，以「工作」分組重新整理，聊天只新增一個導覽項目；LINE「聊天設定」底下的各項放到實際使用的地方，不另設設定群組。

### 4.1 導覽列

當時導覽為「工作空間：工作總覽、報告中心、建立發送、排程管理、聯絡對象、天氣訂閱、發送紀錄」與「管理：LINE OA 管理、帳號與設定」。加入聊天後調整為：

```text
工作總覽                 （新增「未讀聊天」「待處理聊天」數字）

溝通
  聊天                   新增，顯示未讀數
  聯絡對象               現有；標籤與自訂篩選條件在此管理
  案件                   第四階段新增

發送
  建立發送               現有；含「依標籤／依篩選條件」選對象（即 LINE 的篩選傳訊）
  排程管理               現有；含聊天建立的預約訊息
  發送紀錄               現有

管理
  LINE OA 管理           現有
  帳號與設定             現有
```

- 分組標題只是視覺分隔，不可點選；依角色與模組權限隱藏無權使用的項目，整組都無權使用時隱藏該組標題。
- 「聊天」的未讀數與工作總覽的數字來源相同（見第 8 節）。
- 第四階段的「案件」上線前，不顯示該項目。
- 報告中心與天氣訂閱已於 2026-10-05 移除，現行選單見[選單功能](選單功能.md)。

### 4.2 LINE 功能的對應位置

| LINE 官方後台 | 本平台位置 | 理由 |
|---|---|---|
| 聊天 | 溝通 › 聊天 | 新頁面 |
| 聯絡人 | 溝通 › 聯絡對象 | 已有同功能頁面，只補欄位 |
| 篩選傳訊 | 發送 › 建立發送的「選擇發送對象」步驟 | 發送流程只保留一條；另在聯絡對象與聊天列表提供「對這些對象發送」捷徑 |
| 聊天設定 › 基本（提醒） | 聊天頁標題列 ⚙「聊天設定」面板 | 個人瀏覽器偏好，只和聊天有關 |
| 聊天設定 › 標籤 | 聯絡對象頁「標籤管理」 | 標籤屬於聯絡對象，聊天與發送共用 |
| 聊天設定 › 預設訊息 | 聊天輸入區「預設訊息」選單，選單底部「管理預設訊息」開啟管理面板 | 在回覆時使用，就近管理 |
| 聊天設定 › 回應時間 | 聊天頁 ⚙「聊天設定」面板 | 只影響聊天通知 |

| 聊天設定 › 預約訊息 | 發送 › 排程管理（可篩選「來源：聊天」） | 預約只保留一個管理位置 |
| 聊天設定 › 自訂篩選條件 | 聊天列表篩選選單底部「管理篩選條件」與聯絡對象頁，兩處共用同一組資料 | 在篩選的地方管理 |

### 4.3 聊天頁版面

聊天**嵌入現有後台外框**，與其他頁面共用左側選單、頂端工作區／OA 選擇器與登入狀態；不仿照 LINE 另開獨立視窗。理由：

- 共用同一個登入與工作區／OA，不需在兩個視窗之間同步。
- 從聊天前往「編輯聯絡對象」、「建立案件」、「建立發送」不需切換視窗。
- 只有一個頁面輪詢新訊息、發出通知，減輕單台 PC 負擔，也不會重複通知。
- 桌面與手機使用同一套版面。

「聊天」頁桌面採三欄，與 LINE 官方後台相同，三欄使用視窗可用寬度；介面依參考 demo 採淡綠導覽、緊湊聊天室列表及寬幅對話區，並套用全站密集版面（`web/density.css`）：

| 區塊 | 內容 |
|---|---|
| 左：聊天列表 | 篩選選單、搜尋、聊天室清單 |
| 中：對話 | 對話標題列（名稱、成員數、待處理／處理完畢、對話內搜尋）、訊息、輸入區 |
| 右：資訊面板 | 聯絡資料卡、工作面板（記事／案件分頁與統計卡） |

- 進入「聊天」頁時，左側功能選單自動收合為只顯示圖示的窄欄（約 64px），滑鼠移上或點擊可暫時展開；離開聊天頁即恢復原本寬度。使用者手動展開後，在本次瀏覽期間維持展開。
- 右側資訊面板可收合，收合時對話區佔滿剩餘寬度；桌面寬度不足 1280px 時預設收合。
- 聊天列表與對話之間可拖曳調整寬度。
- 手機版改為單欄，以面板切換顯示：列表 → 點選後進入對話（標題列有「返回聊天清單」）→ 由標題列開啟資訊面板；工作列表獨立捲動。
- 只顯示目前工作區與 OA 的聊天室。
- 未選聊天室時，中間顯示空狀態說明。

## 5. 聊天列表

| 項目 | 規則 |
|---|---|
| 每列顯示 | 頭像（同源快取端點 `/api/chat/avatar`；無法載入時用名稱首字）、主要顯示名稱（依聯絡人規格「9. 顯示名稱規則」）、最後一則訊息摘要（媒體以圖示與中文類型顯示）、最後訊息時間（今天顯示時間，其餘顯示「昨天」或日期）、未讀數 |
| 釘選與標記 | 每列可切換「釘選」、「星號」、「紅旗」三個個人標記（`POST /api/chat/room-preference`，存在 `chat_room_preferences`，**每位後台人員各自一份**，不影響同事）。星號與紅旗互斥 |
| 排序 | 已釘選者在前（釘選中紅旗 > 星號 > 無標記），其餘依最後訊息時間新到舊；未釘選時的星號／紅旗不影響排序 |
| 分頁 | 每次載入 50 個聊天室（`ROOMS_PAGE_SIZE`） |
| 搜尋 | 聯絡對象名稱與訊息文字 |
| 篩選 | 全部、未讀、待處理、已完成；可「對目前篩選對象發送」（乙、丙級） |
| 已封鎖／已離開 | 仍可查看歷史，標示狀態並停用輸入區 |

## 6. 對話畫面

### 6.1 訊息顯示

| 訊息類型 | 顯示 |
|---|---|
| 文字 | 氣泡，保留換行，網址可點 |
| 圖片 | 縮圖，點擊放大；提供下載 |
| 貼圖 | 顯示「[貼圖]」或貼圖圖片（取得方式待驗證） |
| 影片、音訊、檔案、位置 | LINE 風格媒體氣泡；檔案卡以向量文件圖示標示格式（缺副檔名時預設 PDF 圖示），提供下載或預覽 |
| 無法讀取 | 顯示「無法讀取原始訊息」（例如媒體已過保存期限） |
| 已收回 | 顯示「對方已收回訊息」（現有 `unsent_at`） |
| 引用回覆 | 若 Webhook 帶有被引用訊息資訊，顯示引用框（待驗證） |
| 本平台送出 | 靠右顯示，標示送出者（後台帳號）與送出方式（回覆／push／預約） |

- 群組與多人聊天室：每則訊息顯示發話者頭像與名稱；名稱來自群組成員快取（`group_member_cache`）。
  - 成員姓名由背景程序（`member_profiles.py`，隨頭像同步排程執行）向 LINE 查詢，**不在 Webhook 寫入時同步呼叫**，也會回補既有訊息的發話者。
  - 每輪最多處理 20 位成員，優先處理尚無姓名者；每位成員以 `member_profile_jobs` 記錄租約與重試：失敗時延後重試（15 分鐘起倍增，最長 1 天），成功後 1 天內不重查；失敗時保留已取得的姓名。
  - 尚未取得姓名時顯示「成員（名稱待同步）」；取得後聊天畫面自動更新。
  - 已授權共用給其他 OA 的聊天室，取得的姓名同步寫入對應 OA 的快取，不跨用其他 OA 的資料。
- 依日期加分隔線；連續同一發話者的訊息合併頭像。
- 開啟時載入最近 50 則，往上捲動載入更早訊息。
- 對話內搜尋（階段 C）：輸入關鍵字後跳至命中訊息並標示。

### 6.2 即時更新

伺服器為標準函式庫 HTTP 服務，不使用 WebSocket；以輪詢取得新訊息：

- **目前實作**：每 10 秒輪詢一次（`CHAT_POLL_MS`），同時更新聊天列表與開啟中的聊天室。
- 同一瀏覽器開多個分頁時，只由一個分頁（leader，以 `localStorage` 心跳選出）輪詢並發出通知；leader 超過 30 秒沒有心跳時由其他分頁接手，避免重複通知。

## 7. 傳送訊息

| 項目 | 規則 |
|---|---|
| 輸入 | Enter 送出、Shift+Enter 換行；手機以送出按鈕為主 |
| 回覆方式 | 依 7.1：可免費回覆時以 reply 送出；否則以 push 送出，送出前提示 |
| 輸入區工具 | 預設訊息（見 12.3）。**目前實作**：聊天輸入區只送文字；圖片與預約請使用「建立發送」 |
| 紀錄 | 送出的訊息寫入對話紀錄（方向為 outbound），並保留送出者、方式與結果 |
| 失敗 | 在氣泡旁顯示失敗原因；結果不明時沿用既有「不自動重送」規則 |
| 權限 | 乙、丙級可傳送；甲級與丁級不顯示輸入區（見第 15 節） |

不提供：自動回覆規則、關鍵字回覆、AI 回覆（見第 16 節）。

### 7.1 訊息額度與回覆方式（方案 C）

2026-10-01 決定：本平台作為主要聊天介面，但不強迫付費回覆，由使用者在需要時改用 LINE 官方後台免費回覆。

> **目前實作與下表的差異**：後端在對方最後一則訊息的 `replyToken` 未使用且未滿 60 秒時自動以 reply 送出，用過即清除；否則直接以 push 送出。reply 失敗時不自動改用 push，回傳錯誤。輸入區的免費回覆倒數橫幅已移除，送出 push 前也**尚未**顯示額度提示與確認；下表為目標行為。

| 狀態 | 輸入區顯示 | 送出方式 |
|---|---|---|
| 對方剛傳訊息，`replyToken` 未使用且未滿 1 分鐘 | 綠色提示「免費回覆剩 NN 秒」倒數 | reply，不計額度 |
| 倒數剩 10 秒以下 | 提示改為醒目色，避免使用者以為仍免費 | reply |
| 已超過 1 分鐘、token 已使用或主動傳訊 | 「此則將使用 N 則訊息額度（群組依人數計）」；附「改到 LINE 官方後台免費回覆」連結 | 使用者確認後才以 push 送出 |
| 送出時 reply 失敗（token 已失效） | 不自動改用 push；提示改為付費送出或到 LINE 官方後台回覆 | 使用者再次確認 |

規則：

- **多則合併**：輸入區可先加入最多 5 個訊息框（文字、預設訊息、圖片），一次送出，盡量用完同一次免費回覆；不要拆成多次送出。
- **倒數以伺服器為準**：以伺服器收到 Webhook 的時間計算；倒數僅供參考，最後以 LINE API 回應為準。
- **群組成員數**：push 到群組前，以 `GET /v2/bot/group/{groupId}/members/count` 取得人數顯示預估則數（實作前確認）。
- **不顯示方案與每月額度**：不查詢、不顯示 LINE 方案名稱與每月已用／剩餘額度（2026-10-01 決定不做）；只在送出前提示該則會使用幾則額度。
- **官方後台回覆的缺口**：在 LINE 官方後台回覆的訊息不會出現在本平台（見第 3 節）。對話畫面在該處顯示提示「若曾在 LINE 官方後台回覆，內容不會顯示於此」。

## 8. 聊天狀態與未讀

| 狀態 | 說明 |
|---|---|
| 一般（`open`） | 預設狀態 |
| 未讀（後台內部） | 聊天室有新的使用者訊息、且尚未有後台人員開啟。任一後台人員開啟即視為已讀（`POST /api/chat/mark-read`），團隊共用，不分個人 |
| 待處理（`pending`） | 後台人員手動標記，表示這段對話還需要處理 |
| 已完成（`done`） | 後台人員手動標記；之後若收到使用者新訊息，自動回到「待處理」 |

- 對話標題列的「待處理」、「已完成」為切換按鈕：再點一次目前的狀態即取消，恢復為一般對話（`POST /api/chat/status`）。
- 「未讀」不等於 LINE 使用者端的已讀狀態，也不會讓對方看到「已讀」（若日後確認可用 `markAsReadToken`，另行評估）。
- 聊天狀態只是對話層級的輕量標記；需要多步驟追蹤、等待第三方或結案摘要的事項，從對話「建立案件」（見[案件管理流程規格](案件管理流程規格.md)），兩者不互相自動改寫。

## 9. 右側資訊面板

| 區塊 | 內容 |
|---|---|
| 聯絡資料卡 | 頭像（無法載入時保留姓名首字）、主要顯示名稱，對象類型標在姓名旁；標籤、電話、信箱與備註直接顯示，電話與信箱可點擊撥打／寄信；組織與職稱收在展開區。資料與標籤編輯沿用聯絡對象權限 |
| 工作面板 | 「對話記事」與「關聯案件」兩個分頁、三張統計卡（記事、案件、逾期案件）、搜尋、狀態篩選與排序固定在列表上方，列表獨立捲動、每頁 12 筆；各聊天室保留自己的篩選狀態。詳見[對話記事本管理規格](對話記事本管理規格.md)「6.2」與[案件管理流程規格](案件管理流程規格.md)「17.0」 |

不提供「負責人員」（見第 16 節）。

### 9.1 對話記事本

記事本的欄位、上限、鎖定政策、待辦勾選、分類與標籤治理、回收筒與 API 一律以[對話記事本管理規格](對話記事本管理規格.md)為準；與案件共用的規則見[案件管理流程規格](案件管理流程規格.md)「17. 記事與案件共用規則」。本節早期規劃（標題 40 字、內容 1,000 字、每次載入 20 筆、任何人都可鎖定等）已由該規格取代。

重點摘要：

- 所有新增與編輯都要按「儲存」才生效；唯一例外是 Markdown 待辦方框的勾選會立即儲存。
- 每個聊天室最多 100 筆、置頂 5 筆；內容最多 2,000 字；每則最多 5 個標籤，只能從治理清單勾選。
- 上鎖／解鎖權限依組織防護政策，記事與案件共用同一政策。
- 刪除移至回收筒，30 天內可還原。
- 從訊息建立記事、從範本建立記事、轉為案件均可在聊天畫面完成。

## 10. 聯絡對象頁整合

LINE 官方後台的「聯絡人」是曾傳訊息給帳號的聊天室清單。本平台已有「聯絡對象」頁，不另建頁面，只補欄位與動作：

| LINE 欄位 | 本平台 |
|---|---|
| 姓名 | 主要顯示名稱（可依名稱排序） |
| 標籤 | 現有標籤欄 |
| 類型（好友／群組） | 聊天室類型：個人、群組、多人聊天室 |
| 負責人員 | 不提供 |
| 最近聊天日期 | 最後一則訊息日期（可排序） |
| 「聊天」按鈕 | 開啟該聊天室 |
| 「詳情」按鈕 | 開啟現有「編輯聯絡對象」 |

## 11. 篩選傳訊

LINE 的「篩選傳訊」是依聊天標籤選出客群後建立訊息。本平台併入現有「建立發送」，不另建流程：

- 發送對象選擇新增兩種來源：「依標籤」（選一或多個標籤，指定符合任一／全部）與「依自訂篩選條件」。
- 介面採「可選擇／已選擇」兩欄，顯示每個標籤或篩選條件的聯絡對象數。
- 選定後沿用既有內容編輯、確認與立即／預約發送流程；確認頁顯示總人數與「此類訊息一律計入當月訊息額度」。
- 預約發送以確認當下的名單為準，不在送出時重新計算。

## 12. 聊天設定

以下為各項設定的功能規則；放置位置不另設設定頁，依「4.2 LINE 功能的對應位置」。

### 12.1 提醒（聊天頁 ⚙ 聊天設定）

| 設定 | 說明 |
|---|---|
| 顯示瀏覽器通知 | 有新訊息時顯示系統通知；需瀏覽器授權，未授權時顯示設定說明 |
| 播放音效 | 預設關閉 |
| 通知中預覽訊息內容 | 預設開啟；關閉時只顯示「有新訊息」 |

- 設定屬於個人偏好，存在該瀏覽器，不影響其他後台人員。
- 只在後台頁面開著時通知（輪詢取得）；不提供手機推播或 Email 通知。
- 「非回應時間」不通知（見 12.4）。
- 不提供 LINE 通話相關設定。

### 12.2 標籤（聯絡對象頁 › 標籤管理）

- 清單欄位：標籤名稱、顏色、聊天室數量；可依名稱或數量排序、搜尋。
- 顯示「已用／上限」（每個 OA 100 個，見聯絡人規格「12.3 數量上限」）。
- 建立、改名、改色、刪除；刪除前顯示會從多少個聊天室移除。

### 12.3 預設訊息（聊天輸入區 › 預設訊息）

常用回覆範本，在對話輸入區一鍵帶入後可修改再送出。

| 項目 | 規則 |
|---|---|
| 數量 | 每個 OA 最多 100 則 |
| 欄位 | 標題（1–40 字）、內容（文字，依 LINE 文字訊息上限 5,000 字）、分類（選填，1–20 字） |
| 清單 | 依分類篩選、搜尋標題，顯示「全部（數量）」 |
| 使用 | 對話輸入區開啟選單，以標題或內容搜尋後帶入；帶入後仍可編輯 |
| 權限 | 乙、丙級可建立、編輯、刪除與使用；丁級可查看；甲級只能閱讀 |

只支援文字範本；圖片或卡片訊息使用既有訊息編輯器。

### 12.4 回應時間（聊天頁 ⚙ 聊天設定）

- 設定每週每天的回應時段與時區（預設 Asia/Taipei），可另設例假日。
- 本平台只用來控制通知：非回應時間不顯示瀏覽器通知，聊天列表照常更新。
- 不自動切換回應模式、不自動回覆（LINE 官方後台的自動回應不受本平台控制）。

### 12.5 預約訊息（發送 › 排程管理）

- 列出由聊天畫面建立、預約中或傳送失敗的訊息：發送對象、內容摘要、傳送時間、最後更新者、狀態。
- 沿用既有單次預約與發送紀錄；可在送出前取消。
- 每個 OA 同時預約中的訊息最多 50 則（與 LINE 相同）。

### 12.6 自訂篩選條件（聊天列表篩選選單、聯絡對象頁）

- 管理聯絡人規格「13.2 自訂篩選條件」，每個 OA 最多 10 個：建立、改名、調整順序、刪除。
- 聊天列表的篩選選單與篩選傳訊共用同一組篩選條件。

## 13. 資料模型（概念）

沿用現有資料表，只補必要欄位與新表：

```text
line_messages（補欄位）
```

```text
chat_state             -- 每個 OA 的每個聊天室一筆，團隊共用
- channel_id
- chat_id              -- recipient_id（userId / groupId / roomId）
- status               -- open | pending | done
- last_inbound_at
- last_read_at         -- 團隊共用的內部已讀時間

```

```text
chat_room_preferences  -- 個人的聊天室釘選與標記
- channel_id
- actor                -- 後台人員身分
- recipient_id
- is_pinned            -- 0 | 1
- marker               -- '' | star | flag
```

```text
group_member_cache
- channel_id / group_id / user_id
- display_name         -- LINE displayName
- picture_url          -- LINE pictureUrl（選填）
- fetched_at
```

```text
member_profile_jobs    -- 成員姓名背景查詢的租約與重試
- channel_id / conversation_id / user_id
- next_at              -- 下次可查詢時間（Unix 秒）

- lease_until          -- 處理中租約，避免重複查詢
```

```text
canned_replies         -- 預設訊息，每個 OA 最多 100 則
```

## 14. 保存、匯出與容量（單台 PC）

| 項目 | 預設 | 理由 |
|---|---|---|
| 文字訊息保存 | 5 年 | 文字體積小；與 LINE 進階方案相同 |
| 媒體檔保存 | 1 年，到期刪除檔案、改顯示「無法讀取原始訊息」 | 圖片、影片佔空間，影響備份時間 |
| 下載時機 | **目前實作**：聊天畫面第一次開啟該則媒體時才向 LINE 下載並快取；未被開啟且 LINE 端已過期的媒體無法補抓 | 尚未實作收到時即下載 |
| 單一媒體檔 | 超過 20 MB 不下載，只保留類型與時間 | 避免單檔塞滿磁碟 |
| 媒體總容量 | 達 10 GB 時停止下載新媒體並通知管理員 | 單台 PC 磁碟有限 |
| 匯出 | 單一聊天室匯出為文字檔（時間、發話者、內容），不含媒體檔（`GET /api/chat/export`） | 對應 LINE「下載聊天紀錄」 |

上述數值集中於 `line-oa-archive/limits.py`（`MEDIA_RETENTION_DAYS`、`SINGLE_MEDIA_MAX_BYTES`、`TOTAL_MEDIA_MAX_BYTES` 等），可依主機調整。聊天設定面板可查看媒體容量並手動清理過期媒體（`POST /api/chat/media/cleanup`）。

## 15. 權限

所有身分與權限以[權限與角色規格](權限與角色規格.md)為準。聊天相關重點：

| 等級 | 閱讀對話 | 傳送訊息 | 記事本、案件、聊天狀態、聯絡對象 |
|---|---|---|---|
| 甲級（平台管理員，系統供應商） | 👁 只能閱讀 | — | 👁 只能閱讀 |
| 乙級（管理員） | ✓ | ✓ | ✓ |
| 丙級（操作人員） | ✓（所屬 OA 全部對話） | ✓ | ✓ |
| 丁級（協作人員） | ✓ | —（不顯示輸入區，後端拒絕） | ✓（上鎖權限依組織防護政策） |

- 聊天室釘選與標記為個人設定，乙、丙、丁級皆可使用；甲級不可寫入。
- 視角預覽：甲級只有檢視狀態；乙級預設檢視，點 🔒 切換編輯後依被預覽者等級操作（見權限規格「5. 視角預覽」）。
- 聊天內容、對話記事本、群組成員快取、預設訊息皆依 OA 與工作區隔離（見聯絡人規格「23. Workspace Data Isolation」）。

## 16. 明確不實作

- 負責人員／指派（Assignee）、客服排班、回應時間 KPI。
- AI 聊天機器人、關鍵字自動回覆、自動回覆規則、自動切換回應模式。
- LINE 通話（語音／視訊）與相關設定。
- 對方已讀狀態顯示。
- 與 LINE 官方後台的標籤、記事本、預設訊息同步。
- 手機推播與 Email 通知。

## 18. AI Agent 實作規則

1. 先閱讀本文件與[聯絡人管理規格](聯絡人管理規格.md)、[案件管理流程規格](案件管理流程規格.md)。
