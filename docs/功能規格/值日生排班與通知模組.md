# 值日生排班與通知模組

建立：2026-10-06。狀態：第一至第五階段已實作；LINE FAQ／訂閱入口待第六階段。

## 1. 用途與依據

管理值日生、人員工作分配與 LINE 通知，取代紙本每月打掃工作輪值表。管理人員可建立排班、調整負責人、發布班表，並依工作執行條件提醒相關人員。

初始人員與工作內容參考 [每月打掃工作輪值表](../LINE_NOTE_261006_1.md)，原始圖片見 [LINE_NOTE_261006_1.jpg](../LINE_NOTE_261006_1.jpg)。參考文件的人員編號與工作欄位編號是不同概念，不以相同數字直接建立對應。

本文件為開發規格草案；除使用者已確認的人員與工作內容外，下列互動及技術設計為提案，尚未實作。

## 規則化管理處理草案

將紙本排班慣例轉為明確設定、資料驗證與自動執行流程。管理人員先建立規則，系統依規則產生排班與提醒；日常人工操作集中於補位、代班及例外處理。本節為處理方式草案，尚未實作。

| 管理項目 | 處理方式 |
| --- | --- |
| 人員與代號分開 | 員工身分使用固定識別碼，排班代號作為輪替位置；離職後保留空缺，新員工按生效日補位，歷史紀錄維持原歸屬 |
| 輪換與執行頻率分開 | 每年／每月／每週決定何時換負責人；工作內的每日、每週、每月子項目決定何時做哪些事，可同時生效 |
| 排班自動檢查 | 產生或修改班表時檢查空缺、漏排、衝突、停用人員及通知管道缺漏；未分配工作不可視為已完成排班，需明確處理或保留為待處理 |
| 異動有版本與生效日 | 補位、代班、人員或工作增減保存原因、操作者、版本與生效日；已發布歷史不覆寫，未來排班及待發通知按有效版本調整 |
| 通知依規則執行 | 依設定時間、執行當日的有效負責人、訂閱狀態及通知管道發送；保存逐筆結果，避免重複建立通知 |
| 查詢統一來源 | FAQ、完整班表、個人工作與通知都取自同一份有效已發布班表及執行規則，避免各自維護而產生不一致 |
| 例外由管理人員處理 | 請假、臨時代班、空缺、假日調整、輪換失敗及通知失敗提供提示與處理入口，不自行猜測人選或忽略問題 |

建議作業流程：

1. **建立設定**：維護人員、代號位置、工作子項目、輪換規則、通知時間及可用 OA／對象。
2. **產生與檢查**：系統依目標期間計算分配，列出缺漏與衝突，供管理人員預覽及調整。
3. **確認啟用**：確認班表或自動輪換規則後發布；自動通知另依設定啟用。
4. **按期執行**：依已啟用規則換班、發送月初公告及到期提醒；員工透過 LINE FAQ 查詢最新有效資料。
5. **處理例外**：管理人員處理補位、代班或失敗事項；系統保存異動紀錄並更新尚未開始的相關通知。

自動化應提供可預覽的結果、可追查的紀錄及明確的待處理提示。一般輪換依既定規則執行；規則變更與例外仍由具權限的人員確認，不因程式化而取消管理責任。

## 2. 首期功能

| 功能 | 預期行為 |
| --- | --- |
| 值日生名單 | 支援新增、編輯、移除人員，管理全名、顯示名稱／暱稱、部門、樓層、啟用狀態及 LINE 聯絡對象綁定 |
| 工作項目 | 支援新增、編輯、移除工作，管理名稱、說明、區域、執行條件、是否參與輪替及顯示順序 |
| 排班管理 | 選擇期間建立草稿、手動分配工作、複製上一期及預覽完整班表 |
| 輪替排班 | 可選每年／每月／每週輪換，設定人員與工作順序後產生草稿，不直接發布 |
| 排班調整 | 修改負責人、設定指定期間代班、保存異動紀錄 |
| 班表發布 | 確認後發布，保留版本；未發布草稿不產生正式通知 |
| LINE 通知 | 發布班表通知、工作到期提醒、班表異動通知 |
| 員工訂閱 | 員工透過 LINE 訂閱／取消值日生通知，不需後台帳號 |
| 關鍵字 FAQ | 輸入「值日生」開啟預設選單，可查看整張班表或自己的工作 |
| 通知紀錄 | 查看待發送、處理中、已送出、失敗、取消及結果不明的紀錄 |

首期不包含員工自行換班審核、打卡、完成回報、照片驗收或績效統計。後續擴充另訂規格。

## 3. 人員與工作設定

### 3.1 人員

- 原表每位員工有排班代號；初始名單包含 16 位具名員工及代號 12 的空缺位置。「X」表示該代號原員工已離職，目前尚無補位者，不是員工姓名或休息標記。
- 排班代號／位置與員工身分分開管理。原員工離職後保留代號位置，標記為「X（待補位）」；新員工可自指定生效日接任該位置，使用新的員工識別碼，不覆寫離職者的歷史排班。
- 空缺位置可保留在輪替順序中；輪替產生的工作若落在空缺位置，顯示未分配並提示管理人員指定代班，不當作休息或已完成分配，也不向離職者發送通知。
- 排班人員與網站登入帳號分開，接收通知不需要後台帳號。
- 人員使用固定識別碼；姓名、暱稱或部門變更不改變歷史排班歸屬。
- LINE 綁定由管理人員選擇目前組織、指定 OA 下的個人聯絡對象，不以 LINE 顯示名稱自動配對。
- 未綁定 LINE 者仍可排班，發布前顯示無法收到個人通知的名單。
- 人員停用後不列入新輪替；已發布的未來工作提示管理人員重新分配，不自動換人。

- 可隨時新增或移除人員。已有排班紀錄者採停用方式移出名單，保留歷史資料；無引用紀錄者可刪除。新增人員需設定加入輪替的生效日與位置。

### 3.2 工作

每個工作包含固定識別碼、名稱、說明、區域、啟用狀態、排序、輪換週期及執行子項目。是否允許多人共同負責需明確設定。

- 「空白欄」保留為來源說明，未命名且未設定內容前不產生執行提醒。
- 「休息」可作為輪替位置，不產生工作提醒。
- 每週指定日、每月 15 號前／16 號後及一年一次，分別儲存為可設定的條件，不單靠文字解析。倒垃圾日依最新需求為每週一、四；資源回收日維持原清單設定，分開管理。
- 負責人輪換週期可選每年、每月、每週，與工作執行頻率分開設定。同一班表可同時包含每月與每年輪換的工作。
- 同一工作可新增多個執行子項目，各自設定每日、每週、每月或年度指定日期的執行內容與提醒；這些條件同時生效。每月 15 號前／16 號後不等於只在 15／16 號執行。
- 可新增或移除工作及執行子項目。已有歷史紀錄者採停用；變更需設定生效日，提示受影響排班與待發通知，確認新版後套用。
- 「剩最後 1 包時購買垃圾袋」屬條件式工作，首期保留在工作說明，未建置庫存回報前不自動判斷觸發。
- 年度工作需設定實際執行日期；僅有「一年一次」時不自行猜日期。
- 參考表中的部分區域或工作名稱仍可由管理人員校正，修改後不覆寫已發布版本的內容快照。

### 3.3 輪換與執行頻率範例

目前工作以每月輪換為主，部分工作每年輪換；年度執行與年度換人仍是兩個獨立設定。

「掃地與擦拭（主機區域）」可設定如下：

| 設定 | 內容 |
| --- | --- |
| 負責人輪換 | 每月一次 |
| 每日子項目 | 掃地、擦拭櫃子與桌椅灰塵 |
| 每週子項目 | 每週二拖地 |
| 每月子項目 | 若另有月度工作，可加上指定日期與內容，與上述子項目同時生效 |

週二提醒應包含每日清潔與拖地；其他日僅列當日到期內容。每日是否包含休息日依工作日與排除日期設定。月度子項目目前僅說明設定能力，不新增原表未列出的工作。

## 4. 排班與發布

1. 選擇組織、班表名稱及排班期間，建立草稿。
2. 選擇手動排班、複製上一期或套用已設定的輪替規則。
3. 顯示工作與負責人矩陣，提供依人員查看當期所有工作的清單。
4. 檢查未分配、停用人員、重複分配及未綁定 LINE 等情況；允許兼任時仍顯示工作數供檢查。
5. 預覽班表、通知內容、通知時間與對象，確認後發布。
6. 發布後的修改形成新版本，要求填寫異動原因；取消舊版本尚未開始的相關提醒，依新版本重建。

同一班表、排班期間只能有一個目前有效的已發布版本；同一工作在同一天不得存在衝突的有效分配。草稿可修改或刪除；已發布及歷史版本保留，不直接刪除。

輪替規則需保存輪換週期（年／月／週）、起始日期、週期邊界、基準分配、人員順序、工作順序、固定工作、空缺／休息位置及每期移動方向與步數。每次以基準日期計算目標期間，不因重複產生而多移動一次。每週需設定一週起始日；每月及每年需設定換班生效日。不同週期的工作分別計算，提醒則查詢執行當日的有效負責人。

人員或工作增減時，預覽新輪替分配、未分配工作及兼任情況，再確認規則的新版本與生效日；保留既有歷史班表，不直接改寫。人數與工作數不一致時提示管理人員處理，不默默丟棄工作。

手動調班只影響指定期間，預設不改變後續輪替基準。固定負責人的工作不參與輪替。紙本各月數字尚未轉錄及確認，不直接推導正式輪替規則。

## 5. 通知設定與內容

### 5.1 已確認的月初與倒垃圾通知

每月 1 日更新當月輪換，當日 **08:30（Asia/Taipei）通知一次所有排班人員**，公告當月負責人與工作分配。這是全員通知，不只通知倒垃圾負責人；個人私訊或群組公告的傳送方式另由通知設定選擇，同一公告不因每個工作更新而重複發送。

自動輪換依已啟用的規則生效；啟用前須確認規則、全員通知範圍與內容預覽。當月有效分配必須在 08:30 通知前完成；若有缺額或輪換失敗，提示管理人員，不發送舊月份班表冒充當月結果。此處為已確認的月初定時公告，與手動發布時的即時通知分開設定，避免重複公告。

倒垃圾工作包含兩個獨立執行子項目，可同時啟用：

| 子項目 | 執行日 | 提醒時間 | 通知對象 | 提醒內容 |
| --- | --- | --- | --- | --- |
| 打包並倒垃圾 | 每週一、週四 | 垃圾車到達時間，可設定，週一與週四可分別設定 | 執行當日有效的倒垃圾負責人 | 打包垃圾，然後拿去倒垃圾 |
| 週末前集中垃圾 | 每週五 | 下班前的通知時間，可設定 | 當週五有效的倒垃圾負責人 | 打包垃圾，拿到一樓集中，等下週一一起丟 |

- 每週五提醒只要求打包與集中，不要求當日倒垃圾。
- 下週一仍按當日有效分配通知倒垃圾負責人，包含一樓集中垃圾；若跨月換人，通知新月份的負責人，不沿用週五的人員。
- 原表的月內前後半月分工若保留，按執行當日日期範圍選擇負責人。
- 垃圾車時間與週五下班前時間未設定時，顯示待設定，不猜測實際時間。
- 全員公告與負責人工作提醒各自建立通知紀錄，同日可分別發送。

### 5.2 通用通知設定

| 通知種類 | 對象與內容 |
| --- | --- |
| 班表發布 | 個人收到自己的當期工作；可另選群組公布完整班表 |
| 工作提醒 | 依日期條件通知當期負責人，同一人同一時段的工作合併呈現 |
| 班表異動 | 通知受影響的原負責人、新負責人；群組公告由設定決定 |
| 手動通知 | 管理人員選擇期間、工作與對象，預覽後立即發送 |

- 個人通知、群組公告分別啟用；群組由管理人員明確選擇，不自動搜尋或猜測。
- 各通知設定發送時間、提前天數及是否啟用；月初公告已確認為每月 1 日 08:30，其他未設定時間的提醒不啟動。
- 使用 `Asia/Taipei` 顯示及計算日期，執行時間以 UTC 保存。
- 各執行子項目可設定每日、每週執行日、月內有效日期範圍、指定日期與排除日期。假日如何處理在確認前採手動設定，不自動套用國定假日。
- 通知內容包含班表期間／版本、執行日期、負責人、工作名稱、工作說明及異動摘要；一般員工不需登入網站才能讀取必要內容。
- 正式啟用前提供預覽與指定對象試送。發布班表與啟用自動通知是分開的操作。

個人提醒範例：

```text
【值日生提醒】2026/10/06（二）
負責人：範例員工01
工作：掃地與擦拭（門口區域）
內容：掃地、擦拭櫃子與桌椅；週二拖地。
範圍：辦公室門外開放區、門口磁磚、2＋3 樓樓梯。
```

以上僅為訊息樣式，不代表範例員工01已被分配該工作。

### 5.3 員工訂閱與「值日生」FAQ

員工直接在 LINE 與指定 OA 互動，不需進入後台或建立網站帳號。輸入「值日生」時回覆預設 FAQ 選單，查詢不會自動訂閱。

| FAQ 選項／關鍵字 | 回覆與行為 |
| --- | --- |
| 值日生 | 顯示功能說明、目前訂閱狀態與下列操作選項 |
| 查看整張班表 | 顯示當期完整已發布班表，包含期間、負責人、工作與版本；可選其他已發布期間 |
| 我的值日生工作 | 列出本人當期工作、每日／每週／每月執行內容，以及最近一次執行日期與提醒時間 |
| 今天的值日生工作 | 列出本人今天到期的執行子項目；沒有到期工作時明確告知 |
| 訂閱值日生 | 啟用本模組通知，回覆訂閱成功與通知種類 |
| 取消值日生訂閱 | 停止本模組的個人主動通知，仍可主動查詢；不取消排班責任 |

- 預設 FAQ 使用固定選項與班表資料查詢；管理員可編輯說明與顯示文字，按鈕與文字指令使用相同權限及查詢邏輯。
- 「我的工作」依目前 OA 的 LINE userId 與排班人員綁定判斷，不讓員工自行輸入姓名冒領身分；尚未綁定時提示聯絡管理員完成綁定。
- 訂閱及查看班表只開放目前組織／OA 已授權的有效員工。訂閱不建立員工、不授予後台權限，也不讓任意 OA 好友讀取內部班表。
- 完整班表只提供已發布內容，不顯示草稿、LINE ID、聯絡資料或內部異動備註。每次查詢及按鈕操作重新檢查資格與有效版本；舊訊息的按鈕不繞過最新權限。
- 沒有當期已發布班表時回覆「本期班表尚未發布」，不以舊月份結果取代。班表過長時分段或分頁呈現，保留查看完整內容的入口。
- 群組中的「值日生」可顯示共用 FAQ；群組必須由管理員授權。個人工作與個人訂閱操作引導至 OA 私訊，避免把個人訂閱狀態公開到群組。
- 訂閱狀態按組織、OA 與員工保存，重複訂閱／取消不重複建立紀錄；其他模組的訂閱不受影響。
- 個人通知發送前檢查訂閱狀態；取消後取消尚未開始的個人通知。封鎖 OA 或人員停用時停止個人通知，恢復後需重新確認有效訂閱。
- 月初 08:30 公告仍以所有排班人員為通知範圍；個人管道依訂閱狀態發送，未綁定／未訂閱者顯示於管理端缺漏名單，不宣稱全員已收到。若另啟用授權群組公告，個人取消訂閱不會停止整個群組的公告。
- 工作提醒只發給已訂閱且在執行當日負責該工作的員工；全員公告不代表每位員工都收到每項工作的到期提醒。

## 6. 發送可靠性

- 排程與逐筆發送結果持久保存，服務重啟後仍可查詢。
- 以班表版本、通知種類、執行日期／時段及收件對象建立唯一鍵，避免重複建立同一次通知；另記錄所包含的工作。
- 發送前重查有效班表版本、通知啟用狀態、組織／OA 狀態及收件對象，停用或失效時取消待發通知。
- 班表更新後，已開始或已送出的紀錄不改寫為未發送；必要時建立有明確異動內容的新通知。
- 明確失敗可由管理人員檢查後重試；逾時或服務中斷導致結果不明時不盲目自動重送。
- 離線期間到期的提醒按可設定補發期限處理；超過期限標記逾期，不能跨日大量補發。補發期限尚待確認。
- API 接受訊息只記為已送出，不表示員工已讀或完成工作。
- 發送沿用現有 OA 憑證與訊息紀錄機制，不另建明文 token 設定。

## 7. 介面與權限

後台新增「值日生」入口，包含「排班管理」、「人員與工作」、「通知設定」、「通知紀錄」。桌面提供週／月／年期間切換及工作分配矩陣；手機以人員／工作清單顯示，沿用現有 Tailwind、亮色與密集版面規範。

- 資料歸屬組織；班表通知指定一個 OA。不同 OA 的 LINE 聯絡對象不可混用。
- 平台管理員、所屬組織管理員可管理；其他操作人員需明確取得本模組權限，不由既有發送權自動推定。
- 「值日生管理員」不另設等級（2026-10-06 決定）：由組織管理員（乙級）對操作人員（丙級）個別授予值日生管理權，可管理人員與工作、排班、通知設定、FAQ 設定及本模組通知紀錄；未授予的操作人員只能檢視，協作人員不顯示本模組。畫面與資料做法見 [值日生模組 UI／UX 規劃](../需求與規劃/值日生模組UIUX規劃.md) 3.1。
- 查看、編輯排班、發布、設定通知及手動發送分別檢查授權。發送時另驗證所選 OA 與收件對象權限。
- 所有讀寫、匯出、通知紀錄與背景發送都由後端檢查組織邊界。
- 保存操作者、操作時間、異動原因及前後版本。員工改名或停用不刪除歷史紀錄。

## 9. 驗收條件

1. 可登錄初始 16 位具名員工並新增、移除人員，正確呈現全名與暱稱；代號 12 保留為「X（原員工離職，待補位）」，空缺工作提示未分配，不向離職者發送通知。補位者自設定日期接任，歷史排班仍歸屬原員工。
2. 可新增、移除工作及執行子項目，保留被引用的歷史資料；可維護工作內容，空白欄與休息不產生執行提醒。
3. 可選每年／每月／每週輪換，同一班表可混合不同週期；可建立指定期間草稿、分配工作、複製上一期，重複產生相同期間的輪替結果一致。
4. 草稿不發正式通知；發布前可查看缺漏、通知對象與完整預覽。
5. 同一工作可同時設定每日、每週、每月子項目；每日清潔＋週二拖地在週二合併提醒，其他日不出現拖地。月中前後範圍及年度指定日期正確處理，換人週期不改變執行頻率。
6. 未綁定 LINE 的人員仍可排班，通知缺漏有明確提示。
7. 修改已發布班表保留歷史版本，舊待發提醒取消，新通知使用新版本。
8. 同一提醒不因重啟或重複提交而重複建立；結果不明可查詢且不自動盲目重送。
9. 停用組織、OA、通知或撤銷授權後，相關未執行通知不再發送。
10. 人員與工作增減後可預覽新輪替並指定生效日，歷史分配不變，未來缺額有提示。
11. 不同組織與 OA 的人員綁定、班表和通知紀錄無法越權存取。
12. 每月 1 日 08:30 以所有排班人員為範圍公告一次當月輪換結果，依個人訂閱或群組設定發送；缺少通知管道者有明確提示，不因多個工作更新重複公告。
13. 每週一、四於各自設定的垃圾車到達時間，只通知當日倒垃圾負責人打包並倒垃圾；週五於設定的下班前時間通知打包至一樓集中。
14. 週五到下週一跨月或換班時，週一通知當日有效負責人處理集中垃圾；未設定工作提醒時間時明確提示且不發送。
15. 有資格員工輸入「值日生」可開啟 FAQ，查看完整已發布班表或本人工作，不需登入後台。
16. 訂閱／取消可重複操作且結果一致；取消停止個人主動通知，但不取消排班或主動查詢資格。
17. 未綁定員工、未授權群組及其他組織的對象無法查詢個人工作或內部班表；群組個人操作引導至私訊。
18. FAQ 在班表異動後查詢最新有效版本，草稿不外露；無有效班表或本人無工作時提供明確回覆。

## 10. 開發前待確認

- 各輪換週期的生效邊界、輪替順序、方向、步數，以及是否有固定人員或固定工作。
- 通知採個人、群組或兩者；使用哪個 OA 與群組。
- 月初全員公告是否需以指定群組確保涵蓋未訂閱個人通知者；目前個人通知尊重訂閱／取消，管理端提示通知缺漏。
- 除已確認每月 1 日 08:30 全員公告外，其他發布通知、到期提醒的時間與提前天數；倒垃圾需填寫週一／四垃圾車到達時間及週五下班前提醒時間。
- 非上班日、請假、代班與逾期補發的處理方式。
- 年度工作的實際日期，以及是否需要多人共同負責同一工作。

可先開發人員、工作、手動排班及發布預覽；自動輪替與自動通知依確認後的設定啟用。


## CSV 匯入／匯出（2026-10-06 新增）

值日人員、工作項目與班表皆提供 `.csv` 匯入／匯出及範本下載。匯入先預覽新增／略過項目與逐列錯誤，再確認整批儲存；任何錯誤均不寫入部分資料。預覽後檔案或既有資料變更，需重新預覽。操作按組織檢查權限並記錄於操作紀錄，不新增資料表。

| 資料 | CSV 欄位與處理 |
| --- | --- |
| 值日人員 | 姓名、英文名/暱稱、部門、樓層、代號、生效日、啟用；支援既有員工清單的樓層／部門／姓名／英文名/暱稱／職稱／分機／備註格式，職稱、分機、備註不寫入值日人員。X 略過；空缺代號可接任，已有人員的代號不覆寫。LINE 綁定不透過 CSV 匯入。 |
| 工作項目 | 工作名稱、說明、區域、類型、輪換週期、允許多人、啟用、生效日、執行內容、執行頻率、星期、每月起始日、每月結束日、年度日期、排除日期、提醒時間、啟用提醒。一列一個子項目，同一工作可有多列；同名工作共用欄位必須一致。匯出最新版本。 |
| 班表 | 班表名稱、期間類型、起始日、結束日、工作名稱、負責人、當期備註、代班原負責人、代班人員、代班起始日、代班結束日。一列一個工作，多筆代班可重複工作列。匯出所選草稿／正式／歷史版本；正式版本採發布時姓名及工作快照。 |

- 匯入人員及工作採新增；同名且內容相同略過，內容不同提示從編輯頁更新，以沿用受影響項目及版本確認。
- 匯入班表需先建好人員及工作，以全名與該期間生效的工作名稱配對；同名無法唯一配對、停用項目、無效或重疊代班都提示錯誤。
- 班表 CSV 只建立草稿；同期間已有草稿時先編輯或刪除，不覆寫既有草稿。已發布班表保留，匯入後依原流程檢查、確認及發布新版本，不直接發送通知。
- 不同輪換週期的分配沿用對應已發布期間，CSV 不得改寫唯讀分配。未列在 CSV 的有效工作仍出現在草稿，交由發布前檢查提示未分配。
- 啟用／允許多人／啟用提醒填 `1` 或 `0`；星期 `1`–`7` 代表週一至週日，多個星期、排除日期或負責人以分號分隔；年度日期填 `MM-DD`，時間填 `HH:MM`。
- 匯出 UTF-8 BOM，支援引號、逗號與多行文字；匯入可選 UTF-8 或 Big5。疑似試算表公式的內容以單引號保護，重新匯入會還原。
- 人員／工作匯入及匯出限管理人員；班表匯入限管理人員，僅查看者可匯出可存取的正式或歷史版本。唯讀預覽不允許匯入。
- 容量沿用 `limits.py`：每檔 2 MiB、最多 6000 資料列，以及既有人員／工作／班表與子項目上限。


## 第四、第五階段實作紀錄（2026-10-06）

通知設定、發送與紀錄及輪替規則、自動輪換已接上原排程。組織預設不啟用通知與自動輪換，OA、垃圾車及週五時間須由管理人員明確設定；通知內容預覽與正式發送分開。補發期限預設 0，排程只容許當分鐘執行，錯過後顯示逾期並取消；可另設分鐘數，上限由 `limits.py` 控制。

倒垃圾捷徑與工作子項目是同一份版本資料，週一／週四／週五分別保存時間；修改後先確認受影響資料，再重新發布班表。提醒讀取執行日的已發布分配及代班，優先採子項目時間，未填則採提醒預設時間，兩者皆空不發。年度未填日期不發，排除日期仍生效。已保存內容有逐筆唯一鍵、重試識別碼與嘗試紀錄，重啟將正在發送轉為結果不明，不盲目重送。重新發布取消舊版本待發提醒，新版重建未來提醒。

輪替規則按組織及年／月／週保存不可覆寫的版本，基準位置與員工身分分開；位置空缺不刪除，按生效接任關係找人。每期從基準日期計算，重複預覽或套用結果一致；固定工作不移動，休息可作為位置且不提醒。邊界支援每週指定起始日、每月／每年的 1–31 日及年度月份，短月取月底。規則增減人員或工作先預覽三期、缺漏與通知範圍，套用草稿另確認差異並清除被套用工作的期間代班。

自動輪換在本期開始後處理，年先於月、月先於週；已有草稿或已發布班表保留人工結果。規則缺漏、未分配或衝突時保留待處理草稿並記錄原因；不發布不完整月份來發月初公告。提前提醒需要未來期間已發布，未發布時不推定分配。

個人正式通知須有本組織、通知 OA、有效綁定與有效訂閱；第六階段尚未接上 LINE 訂閱指令，未訂閱者列在缺漏名單。試送限明確選擇的已綁定人員，前綴為【測試】，使用獨立通知紀錄。群組需明確選擇且屬於通知 OA 與本組織。用量顯示已知個人 push 和群組請求數，群組成員用量尚未取得時標示待確認，非完整總額。

使用六張新增資料表：`duty_notice_settings`、`duty_notice_jobs`、`duty_notice_deliveries`、`duty_subscriptions`、`duty_rotation_versions`、`duty_rotation_runs`。延用 v2 附加建表，不變更既有資料及憑證保存方式。接受的推送另存入既有 `line_messages`，值日生通知佇列與結果不混入一般 `send_jobs`／`send_deliveries`。
