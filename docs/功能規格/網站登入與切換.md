# 網站帳密登入與入口切換

更新：2026-09-30。程式與隔離測試已完成；正式入口切換需先完成管理員密碼設定，再調整本機模式與 Cloudflare Access。Cloudflare Tunnel、Webhook 與 LINE 圖片服務保留。

## 第一次設定

**資料庫已重置、尚無帳號時**：從桌面控制台「開啟管理後台」進入本機管理頁 →「帳號與設定」新增自己的 Email，角色選「平台管理員」→「設定登入」→「產生連結」→「在這台電腦設定」。原 Cloudflare 登入不會恢復已刪除的帳號；完成密碼後再執行下方切換步驟。

1. 既有使用者先透過現行 Access 進入後台；右上角「登入設定」可設定自己的網站密碼。密碼至少 15 字元、最多 128 字元，可用句子，不強制特殊符號組合。
2. 若從本機控制台進入，該入口是本機管理身分，沒有 Email 密碼。請到「帳號與設定」，在自己的 Email 旁按「設定登入」→「產生連結」→「在這台電腦設定」。
3. 新後台人員由平台管理員先建立帳號、組織角色及發送範圍，再提供一次性設定連結。連結有效 30 分鐘，重新產生會使舊連結失效；完成密碼設定後必須重新登入。不會自動寄送 Email。
4. 設定密碼不會變更角色；LINE 聯絡對象不能藉由密碼啟用後台。

## 切換成自己的登入頁

在專案根目錄執行：

```powershell
.\.venv\Scripts\python.exe .\line-oa-archive\configure_login.py
.\.venv\Scripts\python.exe .\line-oa-archive\configure_login.py --mode password
Import-Module .\ServiceControl.psm1 -Force
Invoke-LineAction -Action Restart
```

檢查工具會要求至少一位啟用中的平台管理員已有密碼、公開管理網域有效，且沒有立即發送中的工作；只修改 `.env` 的 `ADMIN_AUTH_MODE`，不修改 Cloudflare 設定。切換前請避開即將執行的預約。

先確認本機 `/login` 能使用 Email 與密碼登入，再由 Cloudflare 帳號管理員調整 **Access → 應用程式 → line-admin**：僅在 `line-admin.stack-base.com` 的應用程式加入 **Bypass／略過** 原則，Include 選 **Everyone／所有人**。保留原有允許原則方便回復；不要修改其他應用程式或 Tunnel。Bypass 會略過 Access 驗證，後續由本網站驗證登入。[Cloudflare Access 原則說明](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/)

以無痕視窗開啟 `https://line-admin.stack-base.com/`，應導向同網域 `/login`，不再跳至 `cloudflareaccess.com`。未登入呼叫 `/api/session` 應為 JSON 401；登入後依原有組織／角色／範圍顯示資料。

本專案無 Cloudflare 帳號管理連線，程式更新與 `.env` 修改不會自動改掉該外部原則。測試請直接開啟 `https://line-admin.stack-base.com/`，不要重開已複製的 `cloudflareaccess.com/cdn-cgi/access/login/...` 舊網址。若直接網址仍轉至 Access，檢查原則是否已儲存且套用至正確網域；若回傳「請從本機控制台或已設定的 Cloudflare Access 管理入口登入」JSON，表示請求已到後台，需確認管理員密碼已設定、`ADMIN_AUTH_MODE` 已切成 `password`。

## 登入與恢復

- 一般登入：瀏覽器 Session Cookie，最長 12 小時；閒置 2 小時失效。
- 保持登入：Cookie 最長 30 天；連續 7 天未使用則失效。此選項只適合私人裝置。
- 登出使目前 Session 失效。修改密碼、完成重設會撤銷該帳號所有網站 Session 及設定連結；平台管理員也能按「撤銷登入」。
- 停用帳號或改變主要角色會撤銷 Session；每次請求重新讀取組織資格與授權，不能用舊 Cookie 取得已撤銷的範圍。
- 忘記密碼由平台管理員重新產生設定連結。平台管理員也忘記時，使用本機控制台進入後台恢復；不用填寫或傳送密碼給開發工具。
- 登入頁支援瀏覽器密碼管理器、顯示／隱藏密碼、亮色介面與手機版。沒有開放註冊、Email 自動發信、LINE Login 或 MFA；不顯示無效的按鈕。

## 驗證與儲存

密碼以 scrypt（N=2^17、r=8、p=1）及隨機 salt 儲存；Session 與一次性連結只在資料庫保存 SHA-256 雜湊。公開站點 Cookie 使用 `__Host-` 前綴、Secure、HttpOnly、SameSite=Lax；本機測試使用不同名稱。所有 Cookie 認證寫入要求同源 Origin 及 Session 綁定 CSRF Token。登入／設定操作有持久化速率限制及密碼雜湊並行限制。參考 [OWASP 密碼儲存](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP Session 管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

登入資料與原有業務資料保存在同一 SQLite 的 `site_credentials`、`site_sessions`、`site_activation`、`site_login_limits`。SQLite、`.env`、執行狀態及切換前備份皆不納入 Git。2026-09-30 已依要求清空資料庫並刪除所有舊備份，目前沒有舊帳號可還原。未來備份應使用 SQLite backup API，不在服務使用中直接複製 WAL 資料庫。

驗證包含 90 項 Python 測試、既有工作台瀏覽器流程、網站啟用／登入／保持登入／改密碼／撤銷／登出，以及深淺各 57 個畫面與狀態的 AA 文字對比。測試使用隔離資料，沒有發送真實 LINE 訊息。

## 回復舊入口

先在 Cloudflare 移除本應用程式的 Bypass 原則，使既有允許 Email 原則恢復，再執行 `configure_login.py --mode cloudflare` 並重啟 LINE 服務。CF Team domain、AUD 與原有允許帳號設定須保留才能回復；Cloudflare Access 與網站 Session 不互相當成登入憑證。備份資料庫只用於必要資料復原，切換模式本身不需還原業務資料。


## 登入後切換工作區與 LINE OA

1. 使用原本的網站帳號密碼登入，不需重新建立平台管理員。
2. 頂端先選個人／組織工作區，再選擇 LINE OA；平台管理員可見所有已授權資料範圍。
3. 「LINE OA 管理」新增帳號時，輸入同一 OA 的 Channel secret 與 Channel access token。畫面僅顯示設定狀態，不回傳憑證。
4. 將該 OA 的 Webhook URL 貼到 LINE Developers → Messaging API，按 Verify 並開啟 Use webhook，再傳一則訊息確認發送對象。
5. 首次匯入的既有 OA 仍使用原本 `/webhook`，不需調整 Tunnel。其他 OA 使用各自的 `/webhook/{channel_id}`。

OA 切換只改變工作資料，不切换登入帳號；視角預覽仍為唯讀。未確認的發送提交必須先查明结果，再切換 OA。工作區歸屬建立後不可從畫面移轉。


## 登入人員與 LINE 名單的區別（2026-10-01 澄清）

登入帳號供後台管理／發送人員使用；LINE 對話對象的分類、標籤與名單管理是另一項功能。CRM 僅為名單操作的舉例，不代表新增 CRM 系統。將對象標記為「同事」「家人」或其他分類，不會建立登入帳號、授予管理權或改變組織資格。聯絡對象仍只需使用 LINE；名單操作受目前工作區／OA 與既有授權限制。


## 案件權限（2026-10-01 新增規劃，待實作）

案件管理為通用功能，不限客服情境；案件由後台人員從有權查看的 LINE 對話建立；可追蹤進度、記錄處理及結案。工作區／OA 的邊界同樣適用於案件及訊息引用。平台管理員可管理全部，組織管理員限於獲授權範圍；其他人員需明確取得案件檢視／處理權，既有發送權不自動包含此權限。聯絡對象仍只在 LINE 對話，不需建立網站帳號。

指派案件承辦人不會自動提升權限；案件內部紀錄及結案操作不會自動通知 LINE 對象。此處為後續權限設計，非現有登入功能已實作的能力。
