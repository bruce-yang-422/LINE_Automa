# 網站登入

更新：2026-10-02。管理後台只使用站內 Email／密碼登入（含首次設定與 `create_admin.py`）；已移除 Cloudflare Access 登入模式與模式切換工具（`configure_login.py`、`remote_auth.py`、`ADMIN_AUTH_MODE`、`CF_ACCESS_*`、`ADMIN_ALLOWED_EMAILS`）。Cloudflare Tunnel 是對外連線通道，與登入無關，繼續保留。

## 入口

| 入口 | 網址 | 驗證 |
| --- | --- | --- |
| 本機控制台 | 桌面控制台「開啟管理後台」（`127.0.0.1:18475`，網址片段帶臨時 token） | 本機管理員，權限等同平台管理員（見[權限與角色規格](權限與角色規格.md) 6.4） |
| 對外網址 | `.env` 的 `ADMIN_PUBLIC_HOST`（經 Cloudflare Tunnel，必須 HTTPS） | 同網域 `/login`，Email＋密碼 |

未設定 `ADMIN_PUBLIC_HOST` 時只接受本機連線。未登入開啟對外網址 `/` 會導向 `/login`；未登入呼叫 API 回傳 JSON 401。

## 第一次設定

依[權限與角色規格](權限與角色規格.md)第 9 節：

1. **有桌面控制台**：資料庫沒有任何啟用中的平台管理員時，從控制台「開啟管理後台」（本機入口）會直接顯示「建立第一位平台管理員」。輸入 Email 與顯示名稱後取得一次性設定連結，本人以連結設定密碼。建立後此頁不再出現。
2. **無桌面主機**：在 `line-oa-archive/` 執行 `create_admin.py`，互動輸入 Email 後印出一次性設定連結。已有平台管理員時，同一指令可新增平台管理員或產生重設密碼連結（緊急復原）；不接受命令列密碼參數，不寫入任何檔案。
3. 從對外網址開啟 `/login` 時，若尚未完成首次設定，只顯示「系統尚未完成初始設定」，不能建立帳號。

之後由平台管理員在「組織」建立組織與管理員帳號並產生設定連結；管理員在「人員與權限」新增操作人員與協作人員。一次性連結有效 30 分鐘，重新產生會使舊連結失效；完成設定後必須重新登入。不會自動寄送 Email。密碼 15～128 個字元，可用一段容易記住的句子，不強制特殊符號組合。首次設定與 `create_admin.py` 的每次使用都寫入操作紀錄。

## 登入與恢復

- 一般登入：瀏覽器 Session Cookie，最長 12 小時；閒置 2 小時失效。
- 保持登入：Cookie 最長 30 天；連續 7 天未使用則失效。此選項只適合私人裝置。
- 登出使目前 Session 失效。修改密碼、完成重設會撤銷該帳號所有網站 Session 及設定連結；平台管理員也能按「撤銷登入」。
- 停用帳號或改變主要角色會撤銷 Session；每次請求重新讀取組織資格與授權，不能用舊 Cookie 取得已撤銷的範圍。
- 忘記密碼由管理員重新產生設定連結。平台管理員也忘記時，從本機控制台進入後台產生自己的設定連結；不用填寫或傳送密碼給開發工具。
- 登入頁支援瀏覽器密碼管理器、顯示／隱藏密碼與手機版。沒有開放註冊、Email 自動發信、LINE Login 或 MFA。

## 驗證與儲存

密碼以 scrypt（N=2^17、r=8、p=1）及隨機 salt 儲存；Session 與一次性連結只在資料庫保存 SHA-256 雜湊。對外網址 Cookie 使用 `__Host-` 前綴、Secure、HttpOnly、SameSite=Lax；本機使用不同名稱。所有 Cookie 認證寫入要求同源 Origin 及 Session 綁定的 CSRF Token。登入／設定操作有持久化速率限制及密碼雜湊並行限制。參考 [OWASP 密碼儲存](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)、[OWASP Session 管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。

登入資料與業務資料保存在同一 SQLite 的 `site_credentials`、`site_sessions`、`site_activation`、`site_login_limits`。SQLite、`.env` 與執行狀態不納入 Git。備份應使用 SQLite backup API，不在服務使用中直接複製 WAL 資料庫。

## Cloudflare 後台的收尾（由使用者操作）

程式不再驗證 Cloudflare Access。部署新版後，到 Cloudflare 後台 **Zero Trust → Access → 應用程式** 刪除 `line-admin` 應用程式（目前為 Bypass 原則）；Tunnel 與其公開主機名稱保留不動。`.env` 中殘留的 `ADMIN_AUTH_MODE`、`CF_ACCESS_TEAM_DOMAIN`、`CF_ACCESS_AUD`、`ADMIN_ALLOWED_EMAILS` 已不再讀取，可直接刪除。

## 介面

登入頁載入 `app.css` 與共用密集版面 `density.css`（見[UI 風格與元件規範](../UI設計/UI風格與元件規範.md)「密集版面」）。登入頁「首次登入或忘記密碼？」說明仍寫「帳號與設定」，實際產生設定連結的位置為「人員與權限」（管理員）或「組織」（平台管理員），文字待修正。

## 登入人員與 LINE 名單的區別

登入帳號供後台人員使用；LINE 對話對象是「聯絡對象」，不屬於任何等級，不需要網站帳號。將聯絡對象標記為「同事」「家人」等標籤，不會建立登入帳號、授予管理權或改變組織資格。各等級可使用的功能見[權限與角色規格](權限與角色規格.md)。
