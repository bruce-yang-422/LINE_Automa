# LINE 訊息格式與編輯器

更新：2026-10-05（對照目前程式確認，內容自 2026-09-30 起無功能變動；圖示改為向量 SVG）。以下「已完成」以本專案程式為準；不代表與 LINE Official Account Manager 的功能完全相同。

## 已完成的操作

「建立發送」提供圖片格式選擇、裝置檔案選擇器、預覽、排序／移除、發送對象選擇、立即或單次預約發送。

| 畫面選項 | 實際 Messaging API 格式 | 目前編輯能力 |
| --- | --- | --- |
| 文字訊息 | `text` | 單則文字、最多 5000 UTF-16 單位 |
| 單圖／多圖 | `image` | 1–5 張，按順序傳送，可調整順序；不是相簿 |
| 圖文卡片 | Flex `bubble` | 一張主圖、標題、說明、HTTPS 連結按鈕 |
| 輪播卡片 | Flex `carousel` | 1–12 張圖文卡片、各自設定按鈕，橫向滑動 |
| 圖文訊息 | `imagemap` | 一張圖片，1／2／4／6 個點擊區域，各區連往不同 HTTPS 網址 |
| 報告來源 | `image` | 從報告中心選擇已授權來源，保留版本與日期確認 |

LINE 的 Push API 每次最多五個 message objects；Flex 輪播內最多十二個 bubble。輪播在本專案以一個 Flex 訊息送出，並非十二個獨立 message objects。[官方 Messaging API 參考](https://developers.line.biz/en/reference/messaging-api/nojs/)

Flex 的圖片、文字與按鈕組成可在手機橫向滑動的卡片；目前提供固定卡片版型，沒有開放任意 JSON 編輯。[官方 Flex 元件](https://developers.line.biz/en/docs/messaging-api/flex-message-elements/)

## 選檔與報告來源

- 在「圖片與互動訊息」點「選擇檔案」，會開啟瀏覽器原生檔案視窗；手機可從手機提供的照片／檔案來源選擇。多圖和輪播可一次選多張，也可分次加入。
- 「報告中心 → 新增報告來源／設定來源」同樣提供選檔。先選組織再上傳，不必輸入 Windows 路徑。
- 接受每張 8 MiB、2000 萬畫素以內的單張 JPG／PNG。後端以實際內容解碼，不只檢查副檔名；拒絕動畫及其他格式。
- 依 EXIF 方向轉正，移除原始中繼資料，長邊縮至最多 2048，再轉為不超過 1,000,000 bytes 的 PNG；必要時減色。此為本專案限制，不能當作 LINE 原圖通用上限。
- 上傳保存當下的副本，不會持續追蹤使用者裝置上的原檔。需要每天自動更新的報告，可展開「進階設定：自動化報告來源」，使用伺服器上的固定 PNG 路徑。
- 圖文卡片主圖採 4:3 裁切；多圖保留完整圖片。圖文訊息高寬比限制為 1:2 至 2:1，使用 1／2／4／6 區的格線縮圖選擇版型；未上傳圖片時也有版型示意。
- 「編輯區域」模式可點擊圖片分區，直接聚焦對應連結欄位；選取欄位也會同步標示圖片區塊。縮減版型再切回，會在目前頁面保留先前各區連結。
- 「模擬點擊」模式隱藏區域格線與編號，點擊後顯示區塊及目的網址；不開啟外部網站、不發送訊息。此為瀏覽器版面示意，實際字體／裁切以 LINE 裝置為準。
- Imagemap 發送時產生寬度 240／300／460／700／1040 的 PNG，透過 `/imagemaps/<隨機識別碼>/<寬度>` 提供給 LINE。[官方 Imagemap 規格](https://developers.line.biz/en/reference/messaging-api/nojs/#imagemap-message)

## 資料與權限

- 私有上傳檔案：`line-oa-archive/data/uploads/<隨機識別碼>.png`；SQLite `upload_assets` 保存名稱、組織、上傳者及時間。原始裝置完整路徑不傳入後端。
- 沒有發送權的帳號（協作人員、平台管理員）不能上傳或發送（聯絡對象沒有後台帳號）；視角預覽預設為檢視狀態，管理員切換為編輯後依被預覽者等級操作（見[權限與角色規格](權限與角色規格.md)「5. 視角預覽」）。組織管理員需具備該組織訊息模組權限。
- 組織管理員的素材強制歸屬目前組織，不能用其他組織的素材 ID。平台管理員可選組織或平台個人素材。
- 組織素材只可發給同組織發送對象。平台個人素材僅平台管理員可用；如需讓組織管理員管理發送紀錄，請上傳為該組織素材。
- 確認發送後才建立隨機公開圖片網址，並確認公開內容與快照相符；公開圖片本身不要求登入，以供 LINE 取圖。尚未提供網址撤銷或到期清理。
- 預約在 `send_jobs.messages_json` 保存已產生的訊息 JSON 與公開快照，不會在到期時重新讀取裝置檔案或編輯草稿。
- 執行前檢查組織、模組、操作人及發送對象。組織素材的發送對象若轉至別的組織，該筆發送取消。沿用每位發送對象的 retry key 與結果不明時不自動重送的規則。
- 上傳檔、資料庫、公開快照與備份均不納入 Git。上傳存檔目前使用隨機檔名，並未實作需求中的入站媒體 Hash 去重。

## 與 LINE OA 後台的差異及後續設計

這是自建 Messaging API 編輯器；預約與紀錄保存於本專案，不會同步到 LINE OA 後台的草稿／預約清單。API 的訊息類型與 OA 後台功能需分別設計。[官方訊息類型](https://developers.line.biz/en/docs/messaging-api/message-types/)

待開發：

1. 草稿庫、素材庫、重複使用版型、圖片裁切與素材清理。
2. 一次發送混合文字、圖片、卡片等最多五則訊息；目前每次選一種格式，多圖除外。
3. 卡片其他版型、多按鈕、訊息／postback action、影片、音訊、貼圖與位置訊息。這些需要各自的驗證、預覽及權限流程。
4. Rich menu 圖文選單為聊天室底部導覽，與本次 Imagemap 圖文訊息不同，需另外管理綁定與生命週期。
5. 每日／每週循環排程、草稿審核、配額顯示及節流。

## 驗證

Python 測試涵蓋圖片內容驗證、JPG 轉 PNG、大小／畫素限制、組織隔離、格式數量、連結限制、六區覆蓋、公開路由白名單、預約快照與發送對象轉組織後取消。

瀏覽器測試涵蓋報告選檔、輪播順序、即時預覽、預約提交內容及手機版圖文訊息；測試資料獨立於正式環境，LINE API 使用模擬。真實 LINE 裝置顯示仍需在指定測試聊天室另行驗收。
