# 範本與分類管理規格與 UI/UX 說明文件（低認知負荷·使用者導向版本）

## 現行精簡基準（2026-10-05）

以下基準取代本文線框中的範例名稱（線框僅示意版面）：內建範本共 6 個（案件 3、記事 3）；記事與案件共用 4 個分類：一般備忘、商務往來、問題處理、待辦交接；預設標籤共 8 個：急件優先、待確認、待追蹤、需回覆、已報價、合約文件、技術支援、交接事項。範本不再各自產生同名標籤。

資料庫版本 2 不相容舊版；全新建庫使用目前預設，啟動不合併或搬移舊分類與標籤。所有系統畫面採密集設計，主內容內距 18px 20px、卡片內距 12px、區塊間距 10–12px、標準控制項 34px、小按鈕 30px、分段切換器 28px、表格垂直內距 8px。

> **核心設計哲學**  
> **「不要求使用者理解『範本系統』，只需要知道『我要做什麼』。」**  
> 全面朝「低認知負荷、零教學 30 秒上手、防呆且容易復原」的方向打造，將底層複雜的資料治理架構隱藏於直覺的任務引導之後。

## 1. 設計願景與重構原則（Vision & UX Principles）

### 1.1 傳統管理後台 vs 使用者導向思維

| 維度 | 舊思維（管理後台／資料治理導向） | 新思維（低認知負荷／使用者任務導向） |
|---|---|---|
| **核心提問** | 「你要管理哪一個 Template Pack 與 Taxonomy？」 | **「你現在想做什麼？」** |
| **首頁呈現** | 複雜 Master-Detail 雙欄、左側一堆 Pack、右側案件記事混排 | **極簡首頁**：搜尋框＋兩顆大任務按鈕＋常用推薦卡片 |
| **新增流程** | 一張長表單塞滿專業欄位（Priority, Category ID, Tags JSON） | **3 步引導精靈（Step-by-Step Wizard）**，每步只做一件事 |
| **結構術語** | Template Pack、Taxonomy、Entity Reference | **「我的範本」、「範本群組」、「分類與標籤」**（人話呈現） |
| **色彩角色** | 賦予 10 種顏色獨立業務意義（需記憶顏色代碼） | **文字為主，顏色為輔**（如 `🔴 緊急`），色弱與新手皆無障礙 |
| **前線套用** | 新增記事 → 點範本 → 跳出二層 Modal → 選擇 Pack → 套用 | **表單頂部即時推薦膠囊**，一鍵點選直接填入，零多層彈窗 |
| **防呆機制** | 頻繁跳出「您確定嗎？」的阻斷式確認窗 | **優先提供「↺ 復原（Undo）」**，降低操作心理壓力 |

### 1.2 八大低認知負荷 UI 準則（8 Golden UI Rules）

1. **一頁一目的**：每個畫面與對話框僅專注於一個主要任務。
2. **一個主要行動點（Single Primary CTA）**：每頁最多一個高亮 Primary Button，引導直覺下一步。
3. **全面使用大白話（Human-readable Language）**：徹底剔除系統術語（不出現 Pack、Taxonomy、Payload 等）。
4. **重要資訊文字優先**：不單靠 Icon 或顏色傳達關鍵狀態，一律伴隨文字標籤。
5. **漸進式揭露（Progressive Disclosure）**：90% 使用者只需前三層功能，進階設定預設收合。
6. **立即反饋與即時預覽（Immediate Feedback）**：編輯過程中即時呈現「卡片完成預覽」。
7. **允許反悔與無痛復原（Undo-first Approach）**：以非阻斷式 Toast +「復原」按鈕取代繁瑣的確認窗。
8. **降低記憶負擔（Recognition over Recall）**：系統主動列出選項與推薦，絕不要求使用者背誦規則。

## 2. 重新定義的資訊架構（Information Architecture）

底層資料庫繼續完整保留 `template_packs`、`case_templates`、`note_templates`、`categories`、`tags` 的多租戶結構，但前端介面全面轉換為使用者心智模型：

```text
範本與分類
│
├── 🏠 首頁（任務導航、全局搜尋、常用推薦、最近使用）
│
├── 📋 我的範本（我平常會用到的標準內容）
│   ├── 全部範本
│   ├── 案件範本（報修、客訴、詢價、交辦任務）
│   └── 記事範本（客戶來電、現場場勘、會議備忘）
│
├── 🏷️ 分類與標籤（整理資料的工具）
│   ├── 分類（單選：這件事「主要是哪一類」）
│   └── 標籤（多選：還有「哪些特徵」）
│
└── ⚙️ 進階設定（漸進式揭露，管理員專用）
    ├── 範本群組管理（原 Template Packs）
    ├── 系統標準範本庫
    └── 啟用／停用與權限治理
```

### 3.3 內容骨架雙格式編輯器（純文字 / Markdown 模式與即時預覽）

為提供彈性且專業的 SOP 流程與檢查清單建立體驗，編輯器全面支援「純文字 / Markdown」雙格式切換：

```text
+--------------------------------------------------------------------+
|  內容骨架 / 檢查清單              [ 純文字 | Markdown ] [ 編輯 | 預覽 ] |
|  +--------------------------------------------------------------+  |
|  | ### 1. 狀況確認                                              |  |
|  | - [ ] 詢問設備型號與故障現象                                 |  |
|  | - [ ] 拍照存證或錄影記錄                                     |  |
|  |                                                              |  |
|  | ### 2. 處置措施                                              |  |
|  | * **優先等級**：重要處理                                     |  |
|  | * **備註**：安排工程窗口                                     |  |
|  +--------------------------------------------------------------+  |
|  💡 支援標題 (###)、檢查清單 (- [ ])、條列 (-)、粗體 (**文字**)、引用 (>) |
+--------------------------------------------------------------------+
```

1. **緊湊單行標頭控制項（Compact Single-Row Header）**：
   - 整合於單一行（`.tmpl-editor-header`），包含欄位標籤、格式膠囊切換鈕（`純文字` / `Markdown`）與編輯/預覽切換鈕（`編輯` / `預覽`，向量圖示），節省縱向空間。
2. **結構化 Block-Level Markdown 解析**：
   - **條列清單緊湊排列**：清單項目自動包覆於標準 `<ul class="md-ul">` / `<ol class="md-ol">` 容器，項目間距緊湊，不產生多餘 `<br>` 堆疊空行。
   - **容許中文無空格標題**：相容 `##標題` 與 `## 標題`，均能正確解析為層次標題。
   - **行內格式與刪除線**：支援行內程式碼 `` `code` ``、粗體 `**text**`、斜體 `*text*`、刪除線 `~~text~~` / `-text-` 及超連結。
   - **互動式檢查清單**：支援 `- [ ]`、`* [ ]`（待辦）與 `- [x]`（完成，帶刪除線）渲染；程式碼區塊內的方框不轉換。範本預覽中僅顯示；套用到記事或案件後，卡片與預覽中的方框可直接勾選並自動儲存（見[對話記事本管理規格](對話記事本管理規格.md)「7.3」）。
3. **偏好記憶與預設純文字（Plain by Default & User Preference Memory）**：
   - 系統初始預設採用「純文字」模式，確保介面最直觀且零學習門檻。
   - 自動記憶使用者最後一次選取的格式偏好（`localStorage: preferred_editor_format`）；若使用者最後一次使用 Markdown 格式，系統將依據其操作習慣在後續新增或編輯時自動預設為 Markdown 模式。

## 4. 人話定義：「分類」與「標籤」的極簡邊界

使用者經常困惑「分類」與「標籤」的差別，介面以一句話清楚定位：

```text
┌───────────────────────────────────────────────────────────────┐
│  📂 分類（只能選 1 個）                                       │
│  用途：「這件事情主要是哪一類？」                             │
│  範例：一般備忘、商務往來、問題處理、待辦交接                 │
└───────────────────────────────────────────────────────────────┘

┌───────────────────────────────────────────────────────────────┐
│  🏷️ 標籤（可以選很多個）                                     │
│  用途：「這件事情還有哪些特徵與備註？」                       │
│  範例：#急件優先、#待確認、#待追蹤、#已報價、#技術支援         │
└───────────────────────────────────────────────────────────────┘
```

- 分類由組織的「分類與標籤管理」維護（乙、丙級）；標籤只能從治理清單勾選，每則記事最多 5 個，撰寫記事時不能臨時新增標籤。

## 5. 無障礙色彩原則：文字為主，顏色為輔

視覺色彩能增進辨識，但不強迫使用者背誦色碼：

```text
【推薦呈現】
🔴 緊急優先      🟠 重要處理      ⚪ 一般進度      🟢 處理完畢

【規範】
1. 任何帶顏色的徽章，文字必須完整顯示（禁止只有一顆紅點而無文字）。
2. 背景色維持 Apple HIG 14%~20% 柔和透明度，文字對比度達 WCAG 2.1 AA（> 4.5:1）。
3. 色彩點選器提供即時縮放與 Focus 環，支援鍵盤 Tab 與方向鍵選取。
```

|  [ 📝 聯絡紀錄 ]   [ 📝 待辦事項 ]   [ 📝 交接備忘 ]   [ 更多範本… ]|

|  記事標題（選填）                                                  |
|  [ 待辦事項 - 王小明                                              ] |
|                                                                    |
|  記事分類                                                          |
|  [ 待辦交接 ▾ ]                                                    |
|                                                                    |
|  記事標籤                                                          |
|  [✓ 待確認 ] [ 急件優先 ] [ 待追蹤 ] …（勾選既有標籤，最多 5 個）  |

|  記事內容                                                          |
|  +--------------------------------------------------------------+  |
|  | ### 事項清單                                                 |  |
|  | - [ ] 待辦內容：                                             |  |

## 7. 刪除操作輕量化與批次管理機制（Low-Profile Trash & Batch Delete）

### 7.1 刪除按鈕輕量化（Icon-Only）
- **卡片底部乾淨清爽**：範本卡片底部僅保留核心行為「檢視大綱」與「編輯」，移除突兀且高警示的紅色實體刪除按鈕。
- **右上角精巧圖標**：刪除功能整合為卡片右上角低調圖標按鈕（`.tmpl-icon-btn.danger`），平時呈現次級灰階向量垃圾桶圖示，滑鼠懸停時微亮提示危險，兼顧簡潔與防呆。

### 7.2 批次選取與批次刪除（Batch Delete）
- **勾選控制**：每張範本卡片標題左側具備獨立核取方塊，勾選後卡片呈現 Apple 藍柔和高亮框（`.tmpl-card.selected`）。
- **工具列全選控制項**：工具列提供「全選 / 已選 N 項」快速勾選器，可一鍵選取當前篩選視圖中的所有範本。
- **批次刪除對話框**：勾選一或多項範本時自動浮現 `[ 批次刪除 (N) ]` 按鈕（向量垃圾桶圖示），點擊後彈出確認對話框，清楚列出即將刪除之範本清單，並提示「不影響既有已建立之案件與記事」。
- **非阻斷式復原（Undo-first）**：刪除完成後呈現附「復原」按鈕的提示（位置依個人設定的通知角落），可一鍵復原；後端 API 為 `POST /api/templates/batch-delete`。

## 8. 系統預設範本庫精簡與自由管理政策（Universal Preset & Full Control）

### 8.1 跨產業通用範本庫（Universal Generic Preset Pack）
- 系統內建「通用（Universal）」範本包，共 6 個範本：
  - 案件範本 3 個：`一般諮詢`（商務往來）、`問題與報修`（問題處理）、`退換補寄與售後`（問題處理）。
  - 記事範本 3 個：`聯絡紀錄`（一般備忘，預設標籤 `待追蹤`）、`待辦事項`（待辦交接，預設標籤 `待確認`）、`交接備忘`（待辦交接）。
- 記事類型與案件類別共用 4 個分類：`一般備忘`、`商務往來`、`問題處理`、`待辦交接`。
- **支援電商與售後工作流**：「退換補寄與售後」內建 SOP 檢查清單（缺貨換款、漏發補寄、瑕疵新品換貨、保固送修及鑑賞期退貨）。
- **不預設細分產業**：避免細分產業預設資料干擾微型團隊與跨領域使用者，行業專屬範本由組織自行建立。
- 舊版內建範本（申請處理、客戶反映）已移除；舊分類與標籤不再於啟動時合併（見[對話記事本管理規格](對話記事本管理規格.md)「7.1.2」、「7.2.2」）。

### 8.2 預設範本支援刪除與直接修改
- **支援刪除內建範本**：使用者可對系統內建預設範本執行個別或批次刪除，刪除紀錄寫入 `deleted_preset_templates` 隔離表，從此不再出現於該工作區。
- **直接編輯內建範本**：點擊預設範本的「編輯」時，系統直接將其轉化為自訂範本並儲存，無縫覆蓋原預設項目，無需繁瑣的「先複製再修改」。

## 9. 漸進式揭露（Progressive Disclosure）：將 Pack 降級為進階群組

- **90% 日常使用者**：在「我的範本」中只看到清晰的卡片清單與「建立範本」按鈕。
- **10% 企業管理員**：切換到「進階設定」分頁才看到範本群組（Pack）管理、各 OA 啟用設定與分類組合套用。範本匯出／匯入尚未實作。
