# 關鍵字訂閱

建立：2026-10-05。狀態：已實作（設定檔版）。

## 1. 用途

聯絡對象在 LINE 傳關鍵字（例如「訂閱天氣」）就能訂閱某類報告。訂閱寫進資料庫，同時輸出成 JSON 名冊，讓外部 Python 發送腳本讀取名冊、搭配[公開圖片素材](公開圖片素材.md)的網址發送。

新增一種報告的流程：

1. 在 `topics.json` 加一個主題（名冊代碼、關鍵字、誰能看）。
2. 寫一支 Python 腳本：產生圖片放進 `media/`，讀 `subscribers/<名冊代碼>.json` 逐一發送。

不需要修改本專案程式，也不需要重新啟動服務。

## 2. 檔案位置

```text
line-oa-archive/subscribers/
├─ topics.example.json   範例設定（會提交到 Git）
├─ topics.json           實際設定（自行維護，不進 Git）
├─ <名冊代碼>.json        各主題名冊（系統產生，不進 Git）
└─ _contacts.json        所有聯絡對象的 ID、名稱與標籤（系統產生，方便填白名單）
```

沒有 `topics.json` 時，關鍵字功能關閉，這些文字只當一般訊息保存。

## 3. 設定檔格式

```json
{
  "status_keywords": ["我的訂閱"],
  "topics": [
    {
      "key": "weather",
      "name": "天氣週報",
      "subscribe": ["訂閱天氣", "訂閱天氣周報", "訂閱天氣週報"],
      "unsubscribe": ["取消天氣", "取消訂閱天氣", "取消天氣周報", "取消天氣週報"],
      "allow": "all",
      "groups": true
    },
    {
      "key": "sales_daily",
      "name": "營業日報",
      "subscribe": ["訂閱營業日報"],
      "unsubscribe": ["取消營業日報"],
      "allow": {"tags": ["主管"], "ids": []},
      "deny": {"tags": [], "ids": ["U0123456789abcdef0123456789abcdef"]},
      "groups": false
    }
  ]
}
```

| 欄位 | 說明 |
|---|---|
| `status_keywords` | 查詢自己訂閱狀態的關鍵字；預設「我的訂閱」 |
| `key` | 名冊代碼，也是名冊檔名；小寫英數字、`-`、`_`，最多 40 字，不可重複 |
| `name` | 回覆訊息顯示的主題名稱，1–40 字 |
| `subscribe`／`unsubscribe` | 訂閱與取消的關鍵字；比對時忽略空白，全部主題的關鍵字不可重複 |
| `allow` | `"all"` 表示所有人；或 `{"tags": [...], "ids": [...]}`，符合任一標籤或 ID 才能訂閱。**省略時沒有人能訂閱** |
| `deny` | 黑名單，格式同上；**黑名單優先於白名單** |
| `groups` | `true` 才允許群組／多人聊天室訂閱，預設 `false` |

- `tags` 是後台「聯絡對象」的標籤名稱，`ids` 是 LINE 的 userId／groupId（可從 `_contacts.json` 複製）。
- 存檔後下一則訊息就套用新規則，名冊最慢 1 分鐘內依新規則重算。
- **JSON 寫錯時沿用上一份有效設定**，錯誤原因寫在服務的錯誤輸出；修正存檔後自動恢復。

## 4. 使用者看到的行為

| 傳送 | 結果與回覆 |
|---|---|
| 訂閱關鍵字（有資格） | 加入名冊；回覆「已訂閱「X」。取消請傳「…」。」 |
| 訂閱關鍵字（不在白名單或在黑名單） | 不加入；回覆「你沒有訂閱「X」的權限，如有需要請聯絡管理員。」 |
| 訂閱關鍵字（群組，但主題 `groups=false`） | 不加入；回覆請改用私訊訂閱 |
| 取消關鍵字 | 移出名冊；回覆「已取消訂閱「X」。」 |
| 「我的訂閱」 | 列出目前訂閱的主題，以及他有資格使用的關鍵字 |
| 封鎖 OA、Bot 離開群組 | 自動取消該對象所有訂閱 |

- LINE 重送同一則訊息時不會重複切換或回覆；較晚到達的舊事件不會蓋掉較新的選擇。
- 群組訂閱後，報告會發給整個群組，**無法擋住群組內沒資格的成員**；敏感報告請維持 `groups: false`。

## 5. 名冊格式（給 Python 讀）

`subscribers/sales_daily.json`：

```json
{
  "topic": "sales_daily",
  "name": "營業日報",
  "generated_at": "2026-10-05T09:00:00+00:00",
  "subscribers": [
    {
      "channel_id": "651c822a…",
      "oa_name": "總公司通知 OA",
      "oa_basic_id": "@abc1234",
      "recipient_id": "U0123…",
      "kind": "user",
      "name": "王小明",
      "tags": ["主管"],
      "subscribed_at": "2026-10-05T08:30:00+00:00"
    }
  ]
}
```

- 名冊**只包含「已訂閱、目前仍有資格、沒有封鎖、OA 啟用中」**的對象；拿掉白名單標籤或加入黑名單後，下次重算就會消失，腳本不需自行判斷權限。
- 重算時機：每次訂閱相關的 Webhook 之後立即重算，並每 60 秒定期重算（反映 `topics.json` 與標籤的變更）。內容沒變時不改寫檔案。
- 寫檔採暫存檔加替換，腳本不會讀到寫一半的檔案。
- 主題從 `topics.json` 移除後，重算時會刪除該主題的舊名冊檔；資料庫中的訂閱紀錄保留，主題加回時恢復。
- 同一份報告只設一個主題，用多個關鍵字涵蓋不同說法（例如「天氣」「天氣周報」「天氣週報」），不要拆成兩個主題，否則會產生兩份名冊。
- 多個 OA 共用同一份主題設定；名冊中每筆有 `channel_id`／`oa_basic_id`，腳本可依 OA 篩選。

## 6. 發送腳本範例

### 6.1 Token 設定（多個 OA）

名冊每筆都有 `oa_basic_id`，發送時必須使用**同一個 OA** 的 Channel access token，否則 LINE 會回錯誤或找不到對象。在 `line-oa-archive/.env` 每個 OA 寫一行：

```env
# 天氣通知小幫手 @123abcde
LINE_CHANNEL_ACCESS_TOKEN_123ABCDE=xxxxxxxx
# 門市營運通知 @987zyxwv
LINE_CHANNEL_ACCESS_TOKEN_987ZYXWV=xxxxxxxx
```

- 名稱規則：`LINE_CHANNEL_ACCESS_TOKEN_` 加上 Bot basic ID 去掉 `@` 後轉大寫。
- 發送只需要 Channel access token；Channel secret 只用於驗證 Webhook，Channel ID 與名冊中的 `channel_id`（本系統內部編號）無關，兩者都不用填。
- LINE 服務不讀這些設定，仍使用管理後台設定、加密存在資料庫的憑證；在 LINE Developers 重發 token 時，兩邊都要更新。

### 6.2 範例

```python
import json
from pathlib import Path
from urllib.request import Request, urlopen

BASE = Path(r"D:\Tools\LINE_Automation\line-oa-archive")

def load_env(path: Path) -> dict:
    env = {}
    for line in path.read_text(encoding="utf-8-sig").splitlines():
        key, sep, value = line.strip().partition("=")
        if sep and not key.startswith("#"):
            env[key.strip()] = value.strip().strip('"').strip("'")
    return env

ENV = load_env(BASE / ".env")

def token_for(basic_id: str) -> str:
    key = "LINE_CHANNEL_ACCESS_TOKEN_" + basic_id.lstrip("@").upper()   # @123abcde → LINE_CHANNEL_ACCESS_TOKEN_123ABCDE
    if not ENV.get(key):
        raise SystemExit(f".env 缺少 {key}")
    return ENV[key]

def push_image(token: str, to: str, url: str) -> None:
    body = json.dumps({"to": to, "messages": [{"type": "image", "originalContentUrl": url, "previewImageUrl": url}]})
    req = Request("https://api.line.me/v2/bot/message/push", data=body.encode(),
                  headers={"Authorization": f"Bearer {token}", "Content-Type": "application/json"})
    urlopen(req, timeout=10).close()

roster = json.loads((BASE / "subscribers" / "weather.json").read_text(encoding="utf-8"))
url = "https://reports.example.com/media/weather/20261005_165917_v001.png"
for s in roster["subscribers"]:
    push_image(token_for(s["oa_basic_id"]), s["recipient_id"], url)
```

- Push 會計入每月訊息額度，群組依人數計算。
- 一次發給多人時可改用 multicast（一次最多 500 個 userId，不能含群組，且必須同一個 OA）。
- 本專案不記錄外部腳本的發送結果；需要紀錄請由腳本自行保存。

## 7. 實作位置

| 項目 | 位置 |
|---|---|
| 程式 | `line-oa-archive/subscriptions.py`（解析設定、資格判斷、處理關鍵字、輸出名冊） |
| Webhook | `app.save_events()` 呼叫 `subscriptions.handle_event()`；`receive_webhook()` 回 200 後重算名冊並回覆 |
| 定期重算 | `recipients.ProfileRefresher.tick()` 呼叫 `subscriptions.periodic_export()` |
| 資料表 | `topic_subscriptions`（訂閱狀態）、`subscription_commands`（已處理的關鍵字訊息） |
| 測試 | `line-oa-archive/tests/test_subscriptions.py` |

既有資料庫會在服務啟動時自動新增這兩張表，不需重建；資料庫版本維持 2。
