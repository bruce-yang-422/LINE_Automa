# 值日生模組 UI／UX 規劃

建立：2026-10-06；同日依 AI 畫面示意（demo，非實作）檢視，補入第 4 節共通規則與 5.1、5.3、5.7、5.9 的正確做法。狀態：規劃／待實作。功能規則以 [值日生排班與通知模組](../功能規格/值日生排班與通知模組.md)（下稱「規格」）為準；本文只規劃畫面、流程與相容做法，不重複規格內容。

視覺與元件沿用 [UI 風格與元件規範](../UI設計/UI風格與元件規範.md)、[UI 配色與對比規範](../UI設計/UI配色與對比規範.md)；權限以 [權限與角色規格](../功能規格/權限與角色規格.md) 為準。

## 1. 與現有後台的相容性檢查

開發前依目前程式（`index.html`、`web/admin.js`、`schema.sql`、`subscriptions.py`、`app.py`）比對，結論如下：

| # | 現況 | 對本模組的影響 | 規劃做法 |
| --- | --- | --- | --- |
| C1 | 權限只有甲乙丙丁四級，「Small Team First」不做逐項勾選；2026-10-05 已移除「操作人員模組授權」 | 規格第 7 節的「值日生管理員」角色、「其他人需明確取得本模組權限」與現行原則衝突 | 已決定：不新增等級，由乙級授予丙級「值日生管理」權（見 3.1） |

## 2. 資訊架構與導覽

```text
側欄 工作空間
  工作總覽 / OA 一覽 / 聊天 / 對話記事本 / 案件管理 / 範本與分類管理
  建立發送 / 排程管理 / 聯絡對象 / 發送紀錄
  ── 模組 ──                       ← 新增 nav-label，僅有啟用模組時顯示
  值日生                            ← data-view="duty"，圖示 calendar（SVG）
```

- 只新增一個側欄項目；模組內以 `msg-nav-segmented` 分頁（與「範本與分類管理」相同模式），網址 `?view=duty&tab=…` 可直接開啟與返回。
- 分頁對應規格第 7 節四個入口：

| 分頁 | `tab` | 內容 |
| --- | --- | --- |
| 排班管理 | `roster`（預設） | 本期摘要、班表期間清單、草稿編輯、輪替規則、發布與版本 |
| 人員與工作 | `people`／`tasks` | 分頁內再以 `segmented` 切換「值日人員」「工作項目」 |
| 通知設定 | `notify` | 通知 OA、各類通知、LINE 查詢與訂閱（FAQ） |
| 通知紀錄 | `log` | 逐筆通知狀態、缺漏名單、重試與取消 |

- 頁面標題列（`heading()`）固定三個膠囊，所有分頁一致：`組織：xxx`、`通知 OA：xxx`、`有效版本：2026/10 v2`（尚無已發布版本時寫「尚未發布」）。不寫「當前 OA」「模組 OA」；草稿沒有版本號，不在頁首顯示草稿版本。
- 頂端 OA 切換器顯示的是目前工作 OA，可能與通知 OA 不同；模組內容不隨它變動（C4）。
- 分頁沿用 `msg-nav-segmented` 膠囊樣式，不另做底線分頁。
- `titles.duty = "值日生"`；Ctrl／⌘ K 搜尋首期不納入值日資料。
- 工作總覽可後續加「今日值日」小卡（只列今日到期工作與負責人），首期不做。

## 3. 角色與可見性

### 3.1 值日生管理員（2026-10-06 決定）

不新增等級。「值日生管理員」是**丙級（操作人員）帳號＋乙級授予的值日生管理權**：

| 等級 | 入口 | 可做的事 |
| --- | --- | --- |
| 甲級 平台管理員 | 不顯示；「組織」頁可開關 `duty_enabled` | 視角預覽唯讀 |
| 乙級 管理員 | 顯示 | 全部：人員、工作、排班、發布、通知設定、試送、手動通知、重試；授予或收回丙級的值日生管理權 |
| 丙級＋值日生管理權 | 顯示 | 與乙級相同的本模組操作；不能再授權給他人 |
| 丙級（未授予） | 顯示 | 只能檢視已發布班表與通知紀錄 |
| 丁級 協作人員 | 不顯示 | 透過 LINE 查詢自己的值日工作（與一般員工相同）；不能被授予管理權 |

- 授予位置：乙級在「人員與權限」的人員列勾選「值日生管理」（與「可用 OA」同一張表多一欄，只對丙級可勾；模組未啟用時不顯示此欄）。資料建議存於 `organization_members.duty_manager`。
- 授予與收回寫入操作紀錄；收回後下次操作即生效，已發布班表與待發通知不受影響。
- 這是唯一的模組層個別授權，不恢復 2026-10-05 移除的通用「操作人員模組授權」。
- 丙級本身仍可使用聊天、案件等既有功能；若之後需要「只能管班表」的帳號，另修權限規格。
- 只能檢視時，編輯、發布、通知按鈕不顯示（非停用），頁首顯示「你目前只能檢視班表」。
- 後端逐項驗證「查看／編輯排班／發布／通知設定／手動發送」，前端隱藏只是輔助。
- 員工收通知、查班表都在 LINE 完成，不需要後台帳號。

## 4. 共通互動規則

- **草稿與正式分開**：草稿畫面頂端顯示黃色提示條「草稿｜尚未發布，不會發送任何通知」；已發布版本顯示綠色「已發布 v3｜2026/10/01 08:12 王小明」。顏色之外一定有文字。
- **影響預覽再確認**：凡會影響已發布班表或待發通知的操作（停用人員、修改工作、改輪替規則、改通知 OA、重新發布），先顯示「受影響項目」清單，再要求填寫原因並確認。
- **生效日**：修改已引用資料時，表單底部固定出現「生效日」欄位，預設下一個期間開始日。
- **未設定就不發**：提醒時間空白一律顯示 `待設定｜不會發送` 徽章，不預填猜測時間。
- **日期顯示**：一律 Asia/Taipei，格式 `2026/10/06（二）08:30`。
- **刪除與停用**：有歷史引用時主按鈕文字直接寫「停用」，不寫「刪除」；可刪除時才顯示「刪除」，並提供既有的「復原」提示。
- **觸控與鍵盤**：手機主要按鈕至少 44px；排序不得只靠拖曳，同時提供「上移／下移」按鈕。
- **主按鈕**：每個區塊最多一個綠色主按鈕，使用 `#00B900` 底＋`#18271D` 深色文字；不使用白字。
- **停用要說原因**：按鈕或開關不能操作時，旁邊以文字說明原因（例如「尚有 2 項必須處理」「需先設定時間」）。
- **不重複入口**：同一動作在同一畫面只出現一次；不另加「快速操作」「流程說明」卡重複頁首或分頁已有的功能。
- **顏色語意**：紅色只用於需要處理的問題（衝突、停用仍被分配、發送失敗）；員工自行取消訂閱、人員停用等正常狀態用灰色。
- **示意與測試資料**：使用 [原始輪值表](../LINE_NOTE_261006_1.md) 的人員與工作（2F、管理部／網路部），不虛構人員、部門或樓層，以便及早看出實際版面。
- **規格外功能不放入畫面**：例如部門清單管理、Excel 匯入、發送「加入通知」、員工完成回報，需先更新規格。

## 5. 頁面規劃

### 5.1 排班管理 › 本期摘要（預設畫面）

```text
值日生      組織：ABC   通知 OA：總公司通知 OA   有效版本：2026/10 v2
[排班管理] 人員與工作  通知設定  通知紀錄
┌ 本期 2026/10（2026/10/01（四）– 10/31（六））  已發布 v2 ─────────┐
│ 16 人 / 15 項工作   今日會提醒的工作 6 項   今日待發通知 2 筆      │
│ ⚠ 需確認：3 人未綁定 LINE                                  ›   │
│ ⚠ 需確認：週一／四垃圾車時間 待設定                          ›   │
│                         [查看班表]  [建立下期草稿]（主按鈕）        │
└──────────────────────────────────────────────────────┘
班表期間                                    ┌ 輪替規則 ───────── [編輯] ┐
期間     狀態    版本  發布人  更新時間        │ 月輪換 13 項／年輪換 2 項   │
2026/11  草稿    —    —      10/05 17:20 [編輯]│ 固定負責人 0 項            │
2026/10  已發布  v2   王小明  10/01 08:12 [查看]│ 自動輪換：未啟用           │
2026/09  已取代  v1   王小明  09/01 08:05 [查看]│ 下次換班：2026/11/01      │
                                            │ 08:30 全員公告            │
                                            └─────────────────────┘
```

- 主按鈕依狀態決定：本期已發布且下期無草稿 →「建立下期草稿」；下期已有草稿 →「繼續編輯 2026/11」；本期未發布 →「編輯本期草稿」。「前往通知設定」不做按鈕，由警示列連過去。
- 統計不使用「需完成」「逾期」等字眼：首期沒有完成回報。「今日待發通知」點擊進入通知紀錄並篩選今日待發送。
- 警示只出現在本期卡片一處，分級沿用 5.3 的三級，不另設「高／中優先」；沒有問題時不顯示。
- 右欄只放輪替規則摘要，依週期分別計數，不顯示「每日 N 人」這類與規格無關的描述。
- 草稿的版本欄顯示「—」；更多選單（⋯）放複製、刪除草稿，需可用鍵盤開啟。
- 沒有任何班表：空狀態「尚未建立班表」＋「先新增值日人員與工作項目」兩步引導（完成自動打勾，樣式同乙級首次登入引導）。

### 5.2 建立草稿

以對話框（手機為底部表單）三步完成：

1. **期間**：期間類型（週／月／年）、起訖日；同期間已有草稿時直接改為「開啟既有草稿」。
2. **起始方式**（三選一卡片）：空白手動排班／複製上一期／套用輪替規則（未設定規則時此卡停用並附「前往設定」）。
3. **確認**：顯示將建立的工作數、預先分配人數，按「建立草稿」進入編輯器。

### 5.3 草稿編輯器

桌面為「矩陣＋右側檢查面板」，1200px 以下檢查面板移到矩陣上方摺疊。

```text
2026/11 草稿                 檢視：[依工作] 依人員    期間：週  [月]  年
┌ 矩陣 ─────────────────────────────────────┐ ┌ 發布前檢查 ──────────┐
│ 工作                 輪換  負責人           │ │ ⛔ 1 項必須處理       │
│ 狗籠、底盤清潔        月    [範例員工03 ▾]      │ │   範例員工02已停用，仍被分配│
│ 每月15號前打包垃圾    月    [範例員工04 ▾]      │ │ ⚠ 3 項需確認          │
│ 男生廁所              月    [未分配 ▾] ⚠    │ │   男生廁所未分配       │
│ 掃地與擦拭（主機區域） 月    [範例員工06 ▾] 代 │ │   範例員工13兼任 2 項      │
│ 休息                  月    範例員工07（休息）   │ │   3 人未綁定 LINE      │
│ 老闆辦公室            年    範例員工05（年度）   │ │ ℹ 空白欄不產生提醒     │
└────────────────────────────────────────┘ └────────────────────┘
                                 [刪除草稿]  [預覽通知]  [發布…]
```

- 草稿提示條（「草稿｜尚未發布，不會發送任何通知」）固定顯示，不提供關閉。
- 發布按鈕在有「必須處理」項目時停用，下方寫「尚有 N 項必須處理」。
- **依工作**：列為工作、依工作項目的顯示順序；格子是負責人選擇器（可搜尋，選項旁顯示該人本期已分配數、是否綁定 LINE）。
- 輪換欄顯示該工作設定的週期（月／年／週／固定）；非目前檢視週期的工作在格子內唯讀，例如月檢視中的年度工作顯示「年度：範例員工05」。
- **代班**格子顯示「原：A → 代：B　11/02–11/02」，不只在代班人旁標「代」；備註欄只放當期備註，不重複工作說明。
- 矩陣不提供列拖曳排序與列勾選：工作順序在「工作項目」與輪替規則調整，首期沒有批次操作。
- 草稿內不提供「新增工作項目」；本期缺少的工作需到「人員與工作」新增，經生效日確認後再出現在草稿。
- **依人員**：每人一張卡，列出本期全部工作與工作數，方便檢查兼任；手機預設此檢視。
- **期間切換**：月檢視一欄負責人；年檢視以 12 個月為欄（對應紙本輪值表），週檢視以週為欄。年度輪換工作在月檢視中顯示為唯讀並註明「年度輪換」。
- **代班**：負責人選擇器內「設定代班…」→ 選代班人與起訖日，只影響該區間，並提示「不改變後續輪替基準」。
- **檢查面板**分三級：⛔ 必須處理（停用人員仍被分配、同工作同日衝突）→ 發布按鈕停用；⚠ 需確認（未分配、兼任、未綁定 LINE、未訂閱、提醒時間待設定）→ 發布時逐項勾選「已知悉」；ℹ 資訊（休息、空白欄），只顯示不需操作。點任一項捲動並聚焦對應格子。
- 未分配歸在「需確認」：規格允許保留空缺，但不默默略過；未分配格子用警示框線＋「未分配」文字。
- 檢查文字指明資料來源，例如「範例員工02已在值日人員中停用，仍被分配」；值日人員停用與聯絡對象停用是兩回事，不混用。
- 依專案規範採手動儲存（不做即時或失焦自動儲存）：標題旁顯示「已儲存 17:21」或「有未儲存變更」；有未儲存變更時切換頁面或分頁需提醒；儲存失敗顯示錯誤且保留輸入。

### 5.4 輪替規則

位於「排班管理」內的次要區塊「輪替規則」，每條規則一張卡（年／月／週分開）。

- 編輯採側邊詳情（手機全頁）：週期與邊界（週起始日／換班生效日）、基準日期與基準分配、人員順序、工作順序、固定負責人工作、休息／空缺位置、移動方向與步數。
- 人員與工作順序以可排序清單呈現，每列附「上移／下移」與「固定」切換。
- 右側即時預覽「接下來 3 期」的分配表，並標示與目前草稿的差異；人數與工作數不一致時顯示 ⚠ 並列出未分配工作。
- 儲存規則新版本時需填生效日；套用到草稿是另一個動作（「套用到 2026/11 草稿」），會先顯示差異再覆寫草稿分配。
- 規則可「停用自動輪換」；啟用自動輪換前顯示規格 5.1 要求的確認：規則、全員通知範圍、內容預覽。

### 5.5 發布

發布對話框沿用 `.steps`：

1. **檢查**：列出 ⚠ 項目並勾選已知悉。
2. **通知預覽**：分頁顯示「個人通知（N 人）」「群組公告」「缺漏名單（未綁定／未訂閱）」；每則可展開看實際訊息內容；顯示預估 push 則數（本次＋自動提醒每月估計），群組依成員數計算並註明。
3. **確認**：重新發布時必填異動原因；顯示「將取消 X 筆舊版本待發提醒，依新版本重建 Y 筆」。勾選「同時立即發送班表發布通知」（預設依通知設定，月初自動公告已涵蓋時預設不勾，避免重複公告）。

發布成功回到本期摘要並顯示既有樣式通知「已發布 2026/11 v1」。發布不等於啟用自動提醒，提醒開關在通知設定。

### 5.6 版本與異動紀錄

已發布班表的「查看」頁右上提供「版本」下拉；選舊版本時全頁唯讀並標示「已取代」。「異動紀錄」以時間軸列出操作者、時間、原因與變更前後（負責人 A → B），資料沿用 `audit_events`。

### 5.7 人員與工作 › 值日人員

```text
值日人員（16）  不需後台帳號，用來排班與發送 LINE 通知     [批次新增] [＋ 新增]
搜尋 [        ]   部門 [全部▾]   LINE [全部｜已綁定｜未綁定]   狀態 [啟用▾]
顯示名稱  全名     部門    樓層  LINE 綁定        訂閱    輪替    狀態
範例暱稱01      範例員工01   管理部  2F   ✓ 範例員工01(LINE)   已訂閱  參與輪替  啟用   [編輯] ⋯
範例暱稱06      範例員工06   網路部  2F   未綁定 綁定›      —       參與輪替  啟用   [編輯] ⋯
```

- 欄位值定義：
  - **LINE 綁定**：「✓ LINE 名稱」或「未綁定」＋「綁定›」連結；「編輯」按鈕固定保留，不被「綁定」取代。
  - **訂閱**：已訂閱／未訂閱（灰）／已取消（灰）／—（未綁定）。
  - **輪替**：參與輪替／固定負責／不參與／「11/01 起加入」（尚未生效）。
  - **狀態**：啟用／停用（灰）。
- 人數少（約 20 人內）時一頁全部列出，不分頁；右側不放統計與快速操作卡，篩選列已能看出未綁定、未訂閱人數（篩選選項旁顯示數量）。
- **批次新增**：貼上多列「全名、顯示名稱、部門、樓層」，先預覽再匯入；用於初始 16 位。「X」列會被標記為空缺並略過。部門為文字欄位，首期不做部門清單管理。
- **LINE 綁定**：底部表單／對話框，只列「通知 OA」的個人聯絡對象（`recipients.kind='user'`），顯示頭像、LINE 名稱、聯絡對象自訂名稱；已綁定給他人的對象標示「已綁定：某某」且不可選。不依名稱自動配對，只提供搜尋。
- **新增**：需選「加入輪替的生效日」與「排在誰之後」。
- **移除**：有排班紀錄 → 按鈕顯示「停用」，對話框列出未來已發布工作，提供「前往重新分配」；無紀錄 → 「刪除」。
- 手機：表格改為卡片清單，LINE 與訂閱狀態以膠囊顯示。

### 5.8 人員與工作 › 工作項目

桌面為「清單＋詳情」雙欄（同記事／案件側欄詳情模式），手機點清單進全頁詳情。

詳情區分組：

| 區塊 | 內容 |
| --- | --- |
| 基本 | 名稱、說明、區域、啟用、類型（一般／休息／空白欄）、是否允許多人共同負責 |
| 負責人輪換 | 每年／每月／每週，或「固定負責人」 |
| 執行子項目 | 可新增多個子項目卡片；每張卡：內容、頻率（每日／每週＋星期膠囊／每月日期範圍＋快捷「1–15 日」「16 日–月底」／年度指定日期）、排除日期、提醒時間（空白＝待設定）、是否提醒 |
| 執行預覽 | 依目前設定列出「接下來 14 天」每天會提醒的子項目，例如「10/07（二）每日清潔＋拖地」「10/08（三）每日清潔」，用來驗證合併結果 |

- 頻率與換人週期在畫面上分開兩個區塊，標題寫明「多久換人」與「多久做一次」。
- 年度子項目沒有指定日期時顯示 `日期待設定｜不會提醒`。
- 「剩最後 1 包時購買垃圾袋」這類條件式內容放在說明欄，子項目類型不提供「條件觸發」選項。
- 修改已被發布班表引用的工作：底部出現「生效日」與「受影響：2026/11 草稿、3 筆待發提醒」，確認後才儲存為新版本。

### 5.9 通知設定

```text
通知 OA  [總公司通知 OA ▾]   變更會讓所有 LINE 綁定失效，需重新綁定
┌ 月初輪換公告 ─────────────── [● 啟用] ┐
│ 每月 1 日 08:30（已確認）  對象：全部排班人員 │
│ 管道：☑ 個人私訊  ☐ 群組 [選擇群組]          │
│ [預覽]  [試送給…]                           │
└─────────────────────────────────────┘
┌ 倒垃圾：打包並倒垃圾 ──────── [○ 停用] ┐
│ 週一 [待設定]  週四 [待設定]  對象：當日負責人 │
└─────────────────────────────────────┘
┌ 倒垃圾：週末前集中 ─────────── [○ 停用] ┐
│ 週五 [待設定]  對象：當週五負責人            │
└─────────────────────────────────────┘
其他：班表發布通知 / 工作到期提醒（預設值） / 班表異動通知      [建立手動通知]
LINE 查詢與訂閱（FAQ）
```

- 每類通知一張卡：啟用開關、時間、提前天數、管道（個人／群組分開勾選）、對象說明、預覽、試送。
- 必填時間未填時開關不可開啟，旁邊寫「需先設定時間」。
- **提醒優先順序**（避免同一工作重複提醒）：工作項目的執行子項目自行設定提醒時間時以子項目為準（例如倒垃圾三張卡即為倒垃圾子項目的捷徑）；「工作到期提醒」只是預設值，套用在沒有自訂提醒時間的子項目。卡片說明寫明此規則，執行預覽與通知預覽依此合併，同一人同一時段只出一則。
- 倒垃圾卡片與「工作項目 › 倒垃圾」子項目是同一份設定，兩處修改互相反映，不另存一份。
- **手動通知**不是開關：以「建立手動通知」按鈕開啟流程，不提供啟用開關與試送。
- 群組只能從「通知 OA」中已授權的群組挑選，不提供自由輸入 ID。
- **試送**：選一位已綁定人員，訊息前加「【測試】」，紀錄類型標為試送。
- **手動通知**：選期間、工作、對象 → 預覽 → 送出，流程同 5.5 第 2、3 步。
- 底部顯示「預估每月 push 則數」摘要。

**LINE 查詢與訂閱（FAQ）** 子區塊：

- 啟用開關、入口關鍵字（預設「值日生」）、說明文字、各選項顯示文字；儲存時檢查與 `topics.json`、本模組其他指令是否撞字（C7），撞字時在欄位下方寫出衝突來源。
- 查詢選項固定為規格 5.3 的五項（查看整張班表、我的值日生工作、今天的值日生工作、訂閱值日生、取消值日生訂閱），每項背後是固定查詢邏輯：只能改顯示文字與排序，不能新增或刪除。訂閱與取消依員工目前狀態擇一出現在回覆中，設定清單兩者都列。
- 授權群組清單：可在群組顯示共用 FAQ 的群組，只能從通知 OA 的群組挑選。
- 右側以 LINE 對話泡泡樣式預覽回覆與 Quick Reply 按鈕（沿用訊息編輯器的預覽元件風格）。

### 5.10 通知紀錄

版面沿用「發送紀錄」：上方統計（待發送／處理中／已送出／失敗／取消／結果不明），篩選（期間、類型、人員、狀態），清單＋側邊詳情。

- 狀態文字沿用 `statusNames`（`accepted` 顯示「LINE 已接受」，並註明不代表已讀或完成）。
- 詳情：執行時間、班表版本、收件對象、包含工作、訊息內容快照、嘗試紀錄與錯誤。
- 動作：`failed` →「檢查後重試」；`pending` →「取消」；`unknown` → 不提供重試，顯示「結果不明，請先向收件人確認」，可手動標記「已確認收到／改為重新發送」，重新發送需確認對話框。
- 「缺漏名單」分頁：最近一次月初公告未能送達的人員與原因（未綁定、未訂閱、封鎖 OA）。

## 6. LINE 端體驗

### 6.1 FAQ 互動

- 回覆為純文字＋Quick Reply；按鈕動作為「傳送文字」，送出內容即為指令文字（例如「我的值日生工作」），與手打文字共用處理流程與權限檢查，舊按鈕也會重查最新資格（C8）。

## CSV 操作補充（2026-10-06）

「值日人員」「工作項目」頁首加入「匯入 CSV」「匯出 CSV」；排班期間清單加入「匯入 CSV」，各班表及編輯器提供「匯出 CSV」。匯出內容來自已儲存資料；正式／歷史班表使用發布快照。

匯入對話框依序提供格式說明、範本下載、檔案選擇、UTF-8／Big5 編碼、未填生效日的預設日期、匯入預覽。預覽顯示新增／略過數、姓名或工作、內容摘要及逐列錯誤；全部檢查通過才出現「確認匯入」。換檔、編碼或日期後重新預覽。班表匯入成功後開啟草稿，保留原有檢查與發布流程。

CSV 操作沿用模組權限，唯讀班表頁提供匯出，不提供匯入。此增補只支援 CSV；Excel `.xlsx` 匯入仍未列入本次範圍。

範本下載入口：值日人員、工作項目、班表期間清單及班表編輯器頁首，均在 CSV 操作旁顯示「CSV 範本」小型文字按鈕。採低調深灰文字、透明背景，懸停加底線；可直接下載，不必先打開匯入對話框。保留對話框內的範本入口。


## 第四、第五階段畫面實作補充（2026-10-06）

通知設定以卡片管理月初公告、工作預設提醒、發布／異動通知，各類型可分別選擇個人私訊及授權群組；倒垃圾三張卡選擇實際工作後讀取原子項目，儲存新工作版本，提示重新發布班表。OA 與管道設定手動儲存；變更 OA 顯示綁定及待發數量並要求原因及確認。手動通知及試送先選範圍，再預覽個人／群組內容、缺漏及已知用量，確認後排入佇列。

通知紀錄支援類型、狀態、期間、人員篩選、狀態統計與展開詳情；顯示內容快照、班表版本、嘗試及錯誤。結果不明提供已確認收到或確認後重新發送，直接重試只允許明確失敗，取消只允許待發。最近月初公告缺漏及排程錯誤另列，群組成員數未知時用量提示待確認。

排班管理下方提供輪替規則與執行紀錄，編輯新版本包含參與位置／工作勾選、上下移、基準位置及固定切換、週期邊界、方向及步數，預覽三期與全員通知摘要。啟用自動輪換須確認預覽及通知範圍；既有人工結果或未完成分配保留待處理。建立草稿可選「建立後預覽輪替差異」，編輯器也可手動套用，均先確認差異。
